## 📌 쉬운 말 요약

**LoRA 한 줄로**: 거대한 모델을 새 일에 맞출 때, **모델 전체를 고치지 않고 작은 부품만 덧붙여 학습**하는 방법입니다.

**비유로**: 두꺼운 교과서 내용을 고치고 싶을 때, 책 전체를 다시 인쇄하지 않고 **필요한 곳에 포스트잇을 붙이는** 것과 같습니다. 원래 책은 그대로 남고, 포스트잇만 바꿔 끼우면 됩니다.

**두 번째 논문 한 줄로**: 포스트잇 방식(LoRA)은 **새 내용을 덜 배우지만, 원래 알던 내용도 덜 잊습니다.** 전체를 다시 쓰면 새 내용을 더 잘 배우지만 원래 내용이 많이 지워집니다.

**우리 연구와의 관계**: 1080 Ti(11GB)로 SmolVLA(6억 파라미터)를 학습시키려면 LoRA 가 필수였습니다. 그리고 1차 학습에서 **원래 100% 하던 태스크가 60% 로 떨어지는 망각**이 생겨서, 두 번째 논문을 근거로 2차 설정을 바꿨습니다.

## 1. 배경 — 큰 모델 전체를 학습시키기 어렵다

SmolVLA 파라미터는 약 6억 개입니다. 전부 학습시키면

| 필요한 메모리 | 크기 (fp32) |
|---|---|
| 가중치 | 2.4GB |
| 기울기 (가중치마다 1개) | 2.4GB |
| Adam 옵티마이저 상태 (가중치마다 2개) | 4.8GB |
| 중간 계산값 | 수 GB |
| **합계** | **11GB 초과** → 1080 Ti 로 불가 |

## 2. LoRA 의 핵심 아이디어

신경망의 대부분은 `출력 = W × 입력` 모양의 행렬 곱입니다. 새 일에 맞추려면 W 를 `W + ΔW` 로 고쳐야 합니다.

LoRA 의 관찰: **"고쳐야 할 양 ΔW 는 생각보다 단순하다."** 그래서 큰 행렬 ΔW 를 **얇은 행렬 두 개의 곱**으로 표현합니다.

```
원래:   출력 = W · 입력                    W: 1024 × 1024 = 100만 개 (얼림 ❄️)

LoRA:   출력 = W · 입력 + B · (A · 입력)
                           A: 1024 × 16  = 1.6만 개 (학습 🔥)
                           B:   16 × 1024 = 1.6만 개 (학습 🔥)
```

- **W 는 얼려두고** A, B 만 학습 → 기울기와 옵티마이저 상태가 A, B 에만 필요
- **16 이 rank(r)** — 얼마나 "두꺼운" 포스트잇인지
- **B 를 0으로 시작** → 학습 시작 순간엔 원래 모델과 완전히 똑같음

## 3. LoRA 작동 원리 — 단계별

1. 모델의 특정 선형층(보통 어텐션의 q, k, v, o projection)에 A, B 를 붙임
2. 원래 가중치는 전부 동결
3. A, B 만 학습
4. **학습이 끝나면 `W ← W + B·A` 로 합침(merge)** → 구조가 원래와 같아져서 **추론 속도 손해 없음**
5. 어댑터(A, B)만 따로 저장하면 수십 MB → 여러 버전을 쉽게 바꿔 끼움

## 4. LoRA 논문 결과

- GPT-3 175B 에서 전체 파인튜닝과 **비슷한 성능**
- 학습할 파라미터 수를 **약 1만 배** 줄이고, GPU 메모리는 약 3배 줄임
- 작은 rank 로도 충분한 경우가 많음

## 5. 두 번째 논문 — 대가는 뭔가?

LoRA 가 공짜는 아닙니다. Biderman 외 (2024) 는 코딩·수학 분야에서 LoRA 와 전체 파인튜닝을 꼼꼼히 비교했습니다.

| | 전체 파인튜닝 | LoRA |
|---|---|---|
| **새 분야 성능** | 더 좋음 | **덜 배움** |
| **원래 능력 유지** | 많이 잊음 | **덜 잊음** ⭐ |
| 망각 방지 효과 | - | weight decay, dropout 보다 좋음 |
| 생성 다양성 | 줄어듦 | 더 유지 |

**왜 덜 배우나?** 전체 파인튜닝이 실제로 만드는 변화 ΔW 의 rank 가 보통의 LoRA 설정보다 **10~100배 크다**는 걸 보였습니다. 얇은 포스트잇으로는 두꺼운 수정을 다 담을 수 없는 겁니다.

**핵심 교훈**: rank 는 **"얼마나 배울까 vs 얼마나 잊지 않을까"** 사이의 손잡이입니다.

## 6. 한계

- 새 과제가 원래와 **많이 다르면** LoRA 로는 부족할 수 있음
- 적절한 rank 는 과제마다 실험으로 찾아야 함

## 7. 내 연구와의 관계

### 참고해서 쓴 곳 1 — LoRA 적용 (`train_lora.py`)

| 항목 | 값 |
|---|---|
| 붙인 곳 | SmolVLA **action expert**(LlamaModel)의 q/k/v/o_proj, gate/up/down_proj |
| 얼린 곳 | VLM, 비전 인코더, 나머지 전부 |
| 학습 파라미터 | **4.92M / 609.8M (0.81%)** (rank 16 기준) |
| 1080 Ti VRAM | **2.67GB** (배치 4) |
| 저장 | 학습 중엔 어댑터만, 끝나면 merge |

action expert 에만 붙인 이유: 체크포인트 원래 설정이 `train_expert_only=True` 이고, 9/14 실험에서 문제가 "지시 이해"가 아니라 "동작 생성"이었기 때문

### 참고해서 쓴 곳 2 — 망각 대응 (LoRA 2차)

LoRA 1차에서 **태스크 1(put the bowl on the stove)이 100% → 60%** 로 떨어졌습니다. 두 번째 논문을 근거로 이렇게 바꿨습니다.

| 설정 | 1차 | 2차 | 근거 |
|---|---|---|---|
| rank | 16 | **8** | rank 가 작을수록 원래 능력을 덜 바꿈 |
| 학습률 | 1e-4 | **5e-5** | 더 조심스럽게 |
| 정상 궤적 섞기 (리허설) | 없음 | **10개 태스크 추가** | 원래 잘하던 것을 계속 보여줌 |
| 균형 샘플링 | 없음 | **태스크별 같은 비중** | 한 태스크(40%)가 독점하지 않게 |

### 주의

rank 를 낮추면 **전환 성공률을 올리는 힘도 약해집니다.** 2차 결과에서 "망각은 줄었는데 전환은 안 늘었다"가 나오면, rank 를 다시 올리고 리허설 비중을 늘리는 쪽으로 조정해야 합니다.

## 8. 용어

| 용어 | 뜻 |
|---|---|
| 파인튜닝 | 사전학습된 모델을 새 데이터로 조금 더 학습 |
| rank (r) | LoRA 행렬의 폭. 클수록 많이 배우고 많이 바꿈 |
| merge | 학습된 B·A 를 원래 W 에 더해 합치기 |
| 어댑터 | LoRA 로 학습한 작은 부품(A, B) 묶음 |
| 망각 (catastrophic forgetting) | 새로 배우다 원래 능력을 잃는 것 |
| 리허설 (rehearsal) | 원래 데이터를 섞어 학습해서 망각을 막는 방법 |
| 동결 (freeze) | 학습하지 않게 고정 |
