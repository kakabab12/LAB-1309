# Hindsight Experience Replay (HER)

- **저자 / 연도 / 학회**: Marcin Andrychowicz, Filip Wolski, Alex Ray, Jonas Schneider, Rachel Fong, Peter Welinder, Bob McGrew, Josh Tobin, Pieter Abbeel, Wojciech Zaremba (OpenAI) / 2017 / **NeurIPS 2017**
- **링크**: https://arxiv.org/abs/1707.01495
- **읽은 날짜**: 2026-09-17 (초록 및 널리 알려진 방법 기준)

---

## 📌 쉬운 말 요약

**한 줄로**: 목표를 못 이룬 실패한 시도라도, **"사실은 그 결과를 원했던 거야"라고 이름표를 바꿔서** 성공 경험으로 재활용하는 방법입니다.

**비유로**: 축구공을 골대 왼쪽 구석에 차려다가 오른쪽 구석으로 들어갔다고 합시다. 보통은 "실패"입니다. 하지만 **"오른쪽 구석에 차는 법"을 배우는 데는 완벽한 성공 사례**입니다. HER 은 이렇게 실패를 "다른 목표의 성공"으로 바꿔서, 한 번의 시도에서 배울 거리를 뽑아냅니다.

**우리 연구와의 관계**: LoRA 1차에서 1→5 전환은 성공을 한 번도 못 해서 데이터가 0개였습니다. 그런데 "접시 밀기"에 실패하는 동안 **우연히 다른 태스크(예: 서랍 열기)를 해낸 경우**가 있다면, 그걸 "서랍 열기 성공 데이터"로 쓸 수 있습니다. LIBERO-Goal 은 10개 태스크가 같은 장면이라 이게 특히 쉽습니다.

---

## 1. 배경 — 실패만 하면 배울 게 없다

목표 달성 여부만 보상으로 주는 과제(예: 블록을 정해진 위치로 밀기)에서

```
시도 1: 목표 ◎, 도착 ●  → 보상 0
시도 2: 목표 ◎, 도착 ●  → 보상 0
시도 3: 목표 ◎, 도착 ●  → 보상 0
...
```

**보상이 계속 0이라** 어느 쪽으로 가야 나아지는지 신호가 없습니다 (희소 보상 문제).

## 2. 핵심 아이디어 — 이름표 바꾸기

실패한 시도를 그대로 버리지 않고, **복사본을 하나 더 만들어 목표를 바꿉니다.**

```
원래 기록:   목표 = ◎(A 위치),  실제로 도착 = ●(B 위치)  → 실패
바꾼 기록:   목표 = ●(B 위치),  실제로 도착 = ●(B 위치)  → 성공!
```

같은 동작인데 **목표만 바꾸면 성공 사례**가 됩니다. 로봇은 적어도 "B 로 가는 법"은 배웁니다. 이게 쌓이면 여러 위치로 가는 일반적인 능력이 생기고, 결국 원래 목표 A 도 할 수 있게 됩니다.

## 3. 작동 원리

1. 목표를 받아서 시도 → 궤적 기록
2. 궤적의 각 순간에 대해
   - **원래 목표**로 한 번 저장
   - **그 궤적에서 나중에 실제로 도달한 상태**를 목표로 바꿔 몇 번 더 저장 (논문의 "future" 방식)
3. 이 모든 기록으로 **목표 조건부 정책**(목표를 입력으로 받는 정책)을 학습
4. 강화학습 알고리즘(DDPG 등)과 함께 씀

## 4. 실험 (논문)

- 로봇팔로 **밀기, 미끄러뜨리기, 집어서 놓기** 과제
- 보상 설계 없이 성공/실패 신호만으로 학습 성공
- HER 없이는 거의 못 배우던 과제를 HER 로 배움
- 시뮬레이션에서 학습한 정책을 실물 로봇에 옮겨 성공

## 5. 확장 — 언어 지시에도 쓸 수 있다

이후 연구들이 HER 을 **언어 지시**로 확장했습니다. 이때 어려운 점은 "실제로 한 일"을 **문장으로 바꾸는 것**입니다. "그릇을 접시에 놓아라" 대신 "그릇을 스토브에 놓아라"로 바꿔야 하는데, 도달한 상태를 보고 알맞은 문장을 만들어야 합니다.

## 6. 한계

- 도달한 상태가 **의미 있는 목표**일 때만 도움이 됨 (그냥 허공을 휘저은 궤적은 바꿔도 쓸모없음)
- 언어 버전에서는 **상태 → 문장** 변환이 필요

## 7. 내 연구와의 관계

### 왜 필요했나

[LoRA 1차](../04_실습/05_libero/lora_v1/README.md)에서 1→5, 2→5 전환은 성공 데이터가 **0개** → 전혀 못 배우고 오히려 0% 로 떨어짐.

### LIBERO-Goal 에서 특히 잘 맞는 이유

위 5번의 "상태 → 문장" 문제가 **거의 공짜로** 풀립니다.

- LIBERO-Goal 10개 태스크는 **같은 장면**
- 각 태스크의 성공 조건(BDDL goal)을 **같은 시뮬레이션에서 전부** 확인할 수 있음
- 그래서 "지금 어떤 태스크가 달성됐나?"를 10개 다 검사하면, 달성된 태스크의 **지시문을 그대로** 이름표로 쓸 수 있음

### 참고해서 쓴 곳

- **`collect_robust_data.py --mode hindsight`** (LoRA 2차 데이터)
  1. A 를 하다 물체를 쥔 채 **그 자리에서** B 로 전환
  2. 전환 시점에 이미 달성된 태스크는 제외하고, 나머지 10개 goal 을 매 스텝 감시
  3. B 성공 → "B 지시문" 으로 저장 (일반 데이터)
  4. B 실패해도, 도중에 **다른 태스크 C 가 달성되면** → 달성 시점까지를 **"C 지시문"** 으로 저장
- 파일 이름: `S*`(B 성공), `H*`(hindsight 로 바꾼 것)

### 기대와 우려

- 기대: 1→5 처럼 B 성공이 0인 쌍에서도 데이터를 건질 수 있음
- 우려: **우연히 다른 태스크를 달성하는 경우가 드물면** 데이터가 거의 안 늘어남 → 2차 결과에서 `H*` 파일 수로 확인

## 8. 용어

| 용어 | 뜻 |
|---|---|
| hindsight (후견지명) | 일이 끝난 뒤에 돌아보고 판단하기 |
| relabeling | 기록의 이름표(목표·지시문)를 바꿔 붙이기 |
| experience replay | 과거 경험을 저장해 두고 다시 꺼내 학습 |
| 목표 조건부 정책 | 목표를 입력으로 받아, 목표마다 다르게 행동하는 정책 |
| BDDL goal | LIBERO 에서 태스크 성공 조건을 적은 논리식 |
