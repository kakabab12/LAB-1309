## 📌 쉬운 말 요약

**한 줄로**: 로봇이 일을 하던 중에 사람이 "아 그거 말고 이거 해줘" 하고 말을 바꿨을 때, **지금 어디까지 했는지 보고** 알맞게 반응하도록 학습시키는 방법입니다.

**비유로**: 식당 직원에게 "콜라 주세요" 했다가 직원이 콜라를 막 집었을 때 "아 사이다로요" 하면, 좋은 직원은 ① 아직 안 집었으면 바로 사이다로 가고, ② 이미 집었으면 콜라를 **제자리에 돌려놓고** 사이다를 가지러 갑니다. SwitchVLA 는 로봇에게 이 판단을 가르칩니다.

**우리 연구와의 관계**: **주제가 거의 같은 논문**입니다. 시뮬레이션도 똑같이 LIBERO-Goal 을 씁니다. 다만 ① 원래 하던 일로 **돌아가는 것(재개)** 은 다루지 않고, ② 전환할 때 **기준 자세로 돌아가는** 방식을 쓰는데 우리는 이걸 금지했고, ③ 재학습이 필요합니다. 이 세 가지가 우리의 차별점입니다.

## 1. 이 논문이 푸는 문제

지금의 VLA 는 "지시 하나 → 처음부터 끝까지 수행" 방식으로 학습합니다. 학습 데이터에 **도중에 지시가 바뀌는 장면이 없습니다.** 그래서 실제로 지시를 바꾸면

- 새 지시를 무시하고 하던 일을 계속하거나
- 들고 있던 물건을 아무 데나 두고 새 일로 달려가거나
- 이상한 자세에서 헤매다 실패합니다

논문은 이걸 "**정적인 태스크 의도(static task intent)를 가정**하기 때문"이라고 표현합니다.

## 2. 핵심 아이디어

전환을 "새 태스크를 처음부터 하는 문제"로 보지 않고, **"지금 실행 상태에 따라 행동을 바꾸는 문제"(behavior modulation)** 로 봅니다.

즉 모델에게 두 가지를 같이 줍니다.

1. 지금 지시문
2. **지금 어디까지 진행했는지** (물체를 만졌는가?)

## 3. 작동 원리 — 단계별

### 3-1. 시연을 "접촉 단계"로 나누기

전문가 시연 영상을 이렇게 구간으로 자릅니다.

```
[접촉 전] ── 물체로 다가감 ──▶ [접촉 중] ── 집어서 옮김 ──▶ [동작 후] ── 내려놓고 물러남
```

이 구간 이름표를 사람이 일일이 붙이지 않고, **손목 카메라 영상을 GPT-4o 에게 보여주며 "그리퍼가 물체를 잡았나?"를 물어서** 자동으로 붙입니다. 그리퍼가 열렸는지 닫혔는지 신호도 함께 씁니다. 실물 데이터 기준 정확도는 약 80.7% 입니다.

### 3-2. 행동 모드 3개

| 모드 | 언제 | 로봇이 하는 일 | 비유 |
|---|---|---|---|
| **forward** | 지시가 그대로일 때 | 하던 대로 계속 | 콜라를 계속 가져감 |
| **rollback** | **물체를 만지는 중에** 지시가 바뀌면 | **방금 한 동작을 거꾸로 되돌림** | 집은 콜라를 제자리에 돌려놓음 |
| **advance** | 물체를 안 만질 때 지시가 바뀌면 | **기준 시작 자세로 선형 이동** 후 새 태스크 | 빈손이면 처음 서 있던 곳으로 갔다가 사이다로 |

### 3-3. 학습 데이터를 따로 만들지 않는다 ⭐ 이게 핵심

"전환 시연"을 새로 녹화하지 않습니다. **기존 시연에서 학습 중에 즉석으로 만들어냅니다** (논문 Algorithm 1, "dynamic data sampling").

학습할 때 각 프레임마다 주사위를 굴려, 지금 지시문을 **그 시연의 지시문(l_i)** 으로 둘지 **다른 태스크의 지시문** 으로 둘지 정합니다. 그러고 나서 정답 동작을 이렇게 만듭니다.

| 조건 | 모드 라벨 | 정답 동작 |
|---|---|---|
| 지시문이 같다 (l_cur = l_i) | forward (b=0) | 시연 동작 그대로 |
| 지시문이 다르고 **접촉 중** (c=1) | rollback (b=1) | 최근 K개 동작 `{a_{t-1} … a_{t-K}}` 을 **역순으로** |
| 지시문이 다르고 **접촉 없음** (c=0) | advance (b=2) | 현재 관절값에서 **기준 시작 자세까지 선형 보간** |

**부록 C (표 6) 가 중요합니다**: 실제 전환 시연을 50~100개 **추가로 모아 넣어도 성능 향상이 미미**했습니다.
→ 필요한 건 "전환 데이터"가 아니라 **모드 라벨(무엇을 해야 하는지)** 이라는 뜻입니다.

### 3-4. 모델 구조

| 부분 | 내용 |
|---|---|
| 백본 | **Florence-2-base** (VLM) |
| 이미지 | DaViT 인코더, 이미지당 50 토큰 |
| 언어 | BART 인코더, 20 토큰 고정 |
| **접촉 상태** | MLP 로 인코딩해 **1 토큰** 추가 → 조건 벡터 41 토큰 |
| 머리(head) | Transformer 디코더가 **3개를 동시에 예측**: ① 접촉 상태(2분류) ② 행동 모드(3분류) ③ 동작 묶음 |
| 동작 묶음 | K=100 예측, 앞 30개를 temporal ensembling 으로 사용 |
| 동작 차원 | 실물 16차원(양팔 7×2 + 그리퍼 2), 시뮬 9차원 |

즉 **접촉 상태를 입력으로 넣고, 모드를 모델이 스스로 예측**합니다. 사람이 모드를 지정하지 않습니다.

## 4. 실험

- 시뮬레이션: **LIBERO-Goal** 태스크 8개, 태스크당 전문가 시연 50개
- 실물: Franka Panda 양팔, 작업대 2곳 × 태스크 4개 × **시연 200개**
- 전환 시점을 early(접촉 전) / mid(접촉 중) / late(동작 후) 로 나눠 쌍 실험, 조건당 **12회**
- 성공 기준: A 가 정해진 단계까지 **실패 없이** 간 뒤, 지시를 바꿨을 때 A 가 **기대한 대로 반응**하고, 이어서 **B 를 완료**해야 성공

LIBERO-Goal 성공률 (%)

| 방법 | 전환 없음 | Early | Mid | Late |
|---|---|---|---|---|
| π0 | 92.3 | 40.7 | 8.3 | 10.2 |
| OpenVLA-OFT | 98.0 | 40.6 | 11.1 | 13.0 |
| **SwitchVLA** | 93.0 | **93.5** | **50.9** | **68.7** |

실물 (작업대 평균, %)

| 방법 | Early | Mid | Late |
|---|---|---|---|
| π0 | 62.5 | **0.0** | 48.3 |
| **SwitchVLA** | **97.2** | **95.8** | **84.7** |

연속 전환 (표 2): 2개 연속 100%, 6개 연속 50~54%. **기준 모델들은 전부 0%.**

**읽는 법**: 기존 모델은 전환만 하면 성능이 40% → 10% 까지 떨어집니다. 특히 **물체를 쥐고 있을 때(Mid)** 가장 나쁩니다(실물에서는 0%). SwitchVLA 는 이걸 크게 끌어올립니다. 그래도 시뮬 Mid 는 50% 대라 여전히 어려운 문제입니다.

## 5. 한계

**논문이 인정한 것**
- "접촉했나"를 진행 정도의 대신으로 써서, 접촉이 없는 추상적인 태스크에는 한계
- 행동 모드가 3개로 고정이라 애매한 지시에 유연하지 않음

- 노이즈가 섞인 피드백·강화학습·열린 환경은 앞으로의 과제

**내가 보기에**
- **재개(원래 일로 돌아가기)를 다루지 않음.** 성공 기준이 "B 완료"라 A 는 버려지는 전제. rollback 은 A 를 **되돌려 없애는** 것이지 나중에 이어서 하는 게 아님
- **advance 가 기준 시작 자세로 선형 보간** — 사실상 리셋이고, **우리 제약(초기 자세 복귀 금지)에 정면으로 걸림.** 우리 [자연스러움 측정](../04_실습/05_libero/naturalness/README.md)에서 원위치 방식은 38cm 더 돌아갔음
- **재학습이 필요** (Florence-2 전체 학습) + 실물에서는 GPT-4o 라벨링 비용. 우리 1080 Ti 로는 불가능한 규모
- **저사양·추론 지연 논의 없음.** 동작 묶음 100개 예측 + temporal ensembling 은 추론이 무거운 방식인데 지연 이야기가 없음. 우리 실측으로는 [0.5초 지연에서 90%→12%](../04_실습/05_libero/latency/README.md)

### 참고해서 쓴 곳

- 전환 시점을 **접근 중 / 잡은 직후 / 들고 이동 중**으로 나눈 실험 설계 → [9/14 전환 실험](../04_실습/05_libero/switch_experiment/README.md)
- `rollback`/`advance` 가 우리 스크립트 `retreat` 와 같은 발상임을 확인 → retreat 을 **최종 방법이 아닌 진단 도구**로 재정의 ([연구주제.md](../연구주제.md))
- **본문 정독 후 새로 얻은 것 (2026-09-18)**
  - 부록 C 가 **우리 LoRA 실패를 설명**합니다. 우리는 "전환 데이터"를 모아 넣었는데(전환 36 + hindsight 47), 논문은 전환 시연을 50~100개 넣어도 **거의 효과가 없다**고 보고했습니다. 필요한 건 데이터 양이 아니라 **"지금 무엇을 해야 하는지(모드)"라는 라벨**입니다 → [LoRA 2차](../04_실습/05_libero/lora_v2/README.md)
  - **접촉 상태를 입력에 넣는다**는 점. LIBERO 에서는 GPT-4o 없이 그리퍼 개폐 + 물체 거리로 **공짜로 계산**됩니다 (`ep.holding()` 이 이미 그 일을 함)
  - rollback 이 **"최근 K개 동작의 역순"** 이라는 점 — 이건 초기 자세 복귀가 **아닙니다.** 우리 제약을 지키면서 쓸 수 있는 유일한 모드입니다 → `--strategy rollback` 구현

### 차별점 (2026-09-18 확정)

| | SwitchVLA | 우리 |
|---|---|---|
| 접촉 없을 때 전환 | **기준 시작 자세로 선형 보간** (advance) | ⛔ 금지 — 그 자리에서 이어감 |
| 접촉 중 전환 | rollback (최근 동작 역순) | 같은 발상을 쓰되 **학습으로 내재화**해 추론 때 스크립트를 안 씀 |
| 중단한 A | 되돌려 없앰 (재개 없음) | **B 후 A 재개**를 별도 지표로 측정 |
| 학습 | Florence-2 전체 학습, 실물 시연 200개/태스크 | **LoRA 0.81%**, 1080 Ti 11GB, 사람 시연 0개 (self-imitation) |
| 추론 지연 | 논의 없음 | **실측 0.56초**를 넣고 평가 (지연에서 90%→12%) |
| 실패 원인 분석 | 없음 | 자세 거리는 원인이 아님(r=+0.14), 판정기로도 후보를 못 고름(Q−V=0.0003) |

2. ~~rollback 이 통하면 그 궤적을 LoRA 로 증류~~ → ❌ **2026-09-18: rollback 은 실패** (19% vs flush 32%).
   되돌아간 거리가 7.7cm 뿐이라 부족했고, [부분 이동은 효과가 없다](../04_실습/05_libero/recovery/README.md)는 것이 확인됨

## 7. 용어

| 용어 | 뜻 |
|---|---|
| behavior modulation | 정책을 통째로 바꾸지 않고, 조건 입력으로 행동 양식을 바꾸는 것 |
| contact phase | 물체와 접촉 전 / 중 / 후 로 나눈 시연 구간 |
| rollback | 방금 한 동작을 거꾸로 되돌리기 |
| advance | 기준 시작 자세로 이동 후 새 태스크 시작 |
| linear interpolation (선형 보간) | 두 자세 사이를 일정한 간격으로 곧게 잇기 |
