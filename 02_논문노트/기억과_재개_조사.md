# 기억과 "중단한 일 재개" — 관련 연구 조사 (2026-09-18)

> **왜 조사했나**: 우리 연구의 두 번째 축은 **"B 를 끝내고 중단했던 A 로 돌아가기"** 입니다.
> 이게 이미 풀린 문제인지, 아니면 아직 빈 자리인지 확인해야 합니다.
>
> **결론: 빈 자리입니다.** 기억 관련 벤치마크와 모델은 빠르게 늘고 있는데,
> **"물체를 쥔 채 중단당하고, 다른 일을 마친 뒤 그 일로 돌아오기"** 를 다루는 것은 아직 없습니다.

| [ReSteer](ReSteer.md) | 2026-03 | 조종 가능성 측정·개선 | ❌ 재개 없음 |

## 2. MEMOBench (2026-09) 자세히

가장 최신이고 **우리와 같은 LIBERO/robosuite 스택**을 씁니다. 기억을 세 가지 조작으로 나눠 각각을 잽니다.

| 조작 | 뜻 | 지표 |
|---|---|---|
| **Storage** (∅→ℳ) | 새로 본 정보를 저장 | MSR |
| **Update** (ℳ→ℳ′) | 외부 상태가 바뀌면 기억을 고침 | MUR |
| **Compression** (ℳ→ℳ̂) | 쌓인 정보를 압축해 정리 | MCR |

측정 방식이 인상적입니다. 기억을 직접 들여다보는 게 아니라, **"기억이 맞다면 환경이 이런 상태여야 한다"는 검사점 술어(predicate)를 시뮬레이터에서 평가**합니다. 우리가 BDDL `goal_state` 로 성공을 판정하는 것과 같은 발상입니다.

**결과**: 6개 모델(π0, π0.5, OpenVLA-OFT, MemoryVLA, HiF-VLA, RoboMME) 중 가장 좋은 것도 **평균 성공률 31.9%**. 저장은 잘하는데 **갱신과 압축이 약하다**는 진단입니다.

**우리에게 주는 것**
- "기억이 맞는지"를 **환경 상태로 검증**하는 설계 → A 재개 평가에 그대로 쓸 수 있음 (우리는 이미 BDDL 술어로 판정 중)
- 기억을 붙인 모델도 31.9% 라는 것 → **기억 모듈을 붙이는 게 쉬운 해답이 아니다**. 9/16 에 "SmolVLA 가 안 되면 MemoryVLA 의 기억 부분만 떼오면 어떨까" 했던 아이디어를 보류할 근거

## 3. 그래서 우리 위치

```
        실행 중 지시 변경          기억이 필요한 긴 태스크
             │                          │
      SwitchVLA, ReSteer          MemoryVLA, MEMOBench, RoboMemArena
             │                          │
             └──────────┬───────────────┘
                        │
              ⭐ 여기가 비어 있다
        "물체를 쥔 채 중단 → 다른 일 → 중단한 일로 복귀"
        + 초기 자세 복귀 금지 + 자연스러움 + 저사양 지연
```

| 축 | 선행 연구 | 우리 |
|---|---|---|
| 지시 변경 | 다룸 (SwitchVLA, ReSteer) | 다룸 + **초기 자세 복귀 금지** 제약 |
| 중단한 일 재개 | **아무도 안 다룸** (LLM 계획기 방식 1편만) | **핵심 지표** |
| 물체를 쥔 상태 | ReSteer·MEMOBench 는 다루지 않음 | **핵심 상황** |
| 자연스러움 | 지표 없음 | 경로 길이·우회 비율·멈춤 횟수·되돌아감 |
| 저사양 추론 지연 | 없음 | 실측 0.56초 반영 |
