# Training-Time Action Conditioning for Efficient Real-Time Chunking

- **저자 / 연도**: Kevin Black, Allen Z. Ren, Michael Equi, Sergey Levine / 2025-12
- **링크**: https://arxiv.org/abs/2512.05964
- **읽은 날짜**: 2026-10-02
- **우리 구현**: `ttrtc.py`, `train_lora.py --rtc-max-delay`, `switch_experiment.py --ttrtc`

## 한 줄로

계산하는 동안 로봇이 이미 할 동작을 학습 때부터 "정답으로 주어진 앞부분"으로 넣어 주고, 모델은 그 뒤만 이어서 만들게 한다.

## 왜 필요한가

동작 묶음(50스텝)을 만드는 데 시간이 걸린다. 그동안 로봇은 이전 묶음을 계속 따라간다. 새 묶음이 도착하면 이미 지나간 앞부분은 버리고 이어 붙이는데, 두 묶음이 서로 모르고 만들어져 이음매가 어긋난다.

[Real-Time Chunking](Real-Time-Chunking.md)(9월에 써 본 것)은 추론할 때 기울기로 앞부분을 맞췄다. 그래서 계산이 느려진다. 이 논문은 같은 일을 학습 때 해 둔다.

## 방법

| | 학습 | 추론 |
|---|---|---|
| 앞 d스텝 | 정답 동작을 그대로 넣는다. 시간값은 "다 만들어진 상태" | 기다리는 동안 실제로 할 동작을 넣는다 |
| 뒤쪽 | 보통처럼 노이즈에서 만든다 | 보통처럼 |
| 손실 | 뒤쪽에서만 잰다 | - |
| d | 0~최대 지연에서 무작위 | 실제 지연 |

필요한 것은 동작 묶음의 **스텝마다 다른 시간값**을 넣을 수 있는 구조뿐이다.

## 결과 (논문)

- 시뮬레이션(Kinetix): 지연 2스텝 이상부터 추론 때 RTC보다 좋고, 지연이 클수록 차이가 커진다.
- 실물(π0.6, 상자 조립, 에스프레소): 추론 때 RTC와 같은 성능, 계산은 더 싸다.

## SmolVLA에 넣을 때 한 일

- SmolVLA는 시간값 하나를 묶음 전체에 복사해 쓴다. 이것을 스텝마다 따로 받게 바꿨다(`embed_suffix`).
- SmolVLA의 시간 규칙은 1이 노이즈, 0이 정답이다. 그래서 앞부분에는 0을 넣는다.
- 묶음 안 동작끼리는 앞쪽만 보게(인과적으로) 되어 있어서, 앞에 넣은 정답을 뒤가 볼 수 있다.
- 끈 상태에서는 원래 모델과 손실·출력이 비트 단위로 같다. 켜면 앞부분이 그대로 유지되는 것까지 확인했다.
- 우리 지연은 11스텝이라 최대 14까지 뽑아 학습한다.
