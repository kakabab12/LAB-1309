# 2026-11-26 웹캠 PiPER 조종: 석사형 VR 조종 방식(follower·MIT·3차 중간 점)과 tinybc 기록 형식에 맞춤

> 한 줄 요약: 석사형이 종이에 설명해 준 VR 조종 구조(손 자세 → 역기구학 → 줄에 넣고 200 Hz 로 꺼내 보냄, 3차 다항식 중간 점, MIT 모드)를 웹캠 조종 서버에 켜는 옵션으로 넣었고, 우리 시범 기록을 석사형 tinybc 의 zarr 형식으로 바꾸는 변환기를 만들었다. 석사형 코드(data.py)로 직접 열어 보니 구조와 배열 설정이 석사형 서버가 만든 것과 같고 값도 원래 기록과 같았다. 모두 가상 팔·가짜 카메라로만 시험했고, 실물 팔(특히 MIT 모드)로는 아직 해 보지 않았다.

## 목표

석사형(찬혁님) 설명: "경로 중간에 생성하기"와 "MIT 추가". 그리고 VR 조종(tinybc)과 웹캠 조종을 합칠 수 있게, 먼저 기록 형식부터 맞추기 (사용자 결정, 1번).

## 한 일

1. **석사형 메모 읽기** (종이 사진). three.js XR 화면 → WebSocket → 서버. squeezeStart 에 기준점(anchor), 자세(4×4)가 오면 `joint = ik(frame)` → `follower.append(joint)`, follower 가 200 Hz 로 `q.popleft()`.
   중간 점 `θ_t = θ0 + s(θ1 − θ0)`, `s = 3t² − 2t³` (처음·끝 속도 0). Bang-Bang 대신 PD (`kp·e + kd·ė`), kp 5·kd 0.8 로 읽힘.
2. **석사형 코드 읽기** (github chanhyuk-jung/tinybc, faster 브랜치, 11/26 커밋 "teleop is much faster with almost no delay").
   follower 는 90 Hz, 줄 길이 1 (가장 새 목표만). 목표를 꺼내면 `Piper.move_joints(목표, 메시지 간격)` 이 그 간격 동안 3차 중간 점을 200 Hz 로 MIT 모드로 보낸다. 코드의 kp 기본값은 20, kd 0.8.
3. **follower 넣기** (`stream.py`, `robot_server --follower-hz 200`). 100 Hz 박자가 푼 관절 목표를 둘로 나눠 줄에 넣고, 따로 도는 쓰레드가 5 ms 마다 하나씩 보낸다.
   줄은 20 ms 어치(4점)로 묶어 넘치면 옛 점을 버린다 (석사형은 WebSocket 이라 순서대로 다 오지만 우리는 UDP). 비면 마지막 점을 속도 0 으로. 점 사이 관절 변화를 3 rad/s × 5 ms 로 한 번 더 자른다.
4. **MIT 모드** (`--mode mit --kp 5 --kd 0.8`, agx-bus `move_mit`). 실물이면 시작할 때 "팔 안의 속도 제한이 없다"는 안내를 더 띄우고, Enter 뒤에 follower 를 켠다 (켜자마자 지금 자세를 붙잡기 시작하므로).
5. **3차 중간 점** (`--profile cubic`, mapping.cubic_s). 11/20 의 패킷 사이 잇기에서 곧은 비율 대신 s(t) 를 쓴다.
6. **기록에 더함**: 관절 속도 `qvel` (실물은 팔이 읽은 값, 가상 팔은 차분), 그리퍼 힘 `grip_force`, 로봇 카메라 사진 품질 85 → 95, 같은 사진이면 같은 JPEG 를 다시 씀, `--top-cam` (= `--front-cam`), 시험용 `--fake-cams`.
7. **변환기** `to_tinybc.py`: `ep_XXX.npz` → tinybc zarr. `actions` = 보낸 관절 + 그리퍼 폭/0.1, `obs/qpos` = 실제 관절 + 폭, `obs/qvel` = 관절 속도 + 그리퍼 힘, `obs/images/wrist·top` (RGB 640x480, JPEG 95), `info/dt`, 그룹 속성 `treespec`·`episode_ends`. 앞뒤 따라가기 꺼진 줄은 자른다.
8. **확인**: 가짜 노트북(손을 움직이며 시범 2개, 두 번째 가운데 0.35초 끊김) → 가상 팔 서버(가짜 로봇 카메라) → 변환 → 석사형 data.py 의 ZarrStore 로 열기, 석사형 서버와 똑같은 설정으로 만든 store 와 배열 설정 비교, 석사형 `write_episode` 로 이어 붙이기.

## 알게 된 것

- 석사형 구조도 우리처럼 "가장 새 목표만" 쓴다 (follower 줄 길이 1). 다른 점은 팔에 보내는 쪽: 메시지 간격 동안 3차로 200 Hz MIT.
- follower 가 "한 번 더 자른 점" 254번은 거의 다 매퍼가 이미 3 rad/s 로 자른 값이 한도와 같아서 센 것이었다 (한 점 가장 큰 변화 = 한도 0.015 rad). 세는 기준을 고쳤다.
- 가짜 손은 초당 15 cm 쯤 움직였는데 관절 2·3번이 자주 3 rad/s 한도까지 돌았다. 저장한 처음 자세가 밑동 가까이(12.8 cm) 접힌 자리라 작은 움직임에도 관절이 많이 도는 것으로 보인다. MIT 로 실물을 움직일 때 알아 둘 점.
- 11/16·11/18 실물 기록은 로봇 카메라 사진이 없어서 tinybc 형식으로 바꿀 수 없다 (변환기가 건너뜀).
- 석사형 코드를 읽어 보면 server.py 가 `mark()` 를 부르지 않고 `mark()` 도 빈 목록이면 아무것도 안 넣어서, 석사형 서버가 쓴 store 는 시범 경계 `episode_ends` 가 비어 있을 것으로 보인다 (실제 store 로는 확인 안 함). 석사형께 알려 드릴 것.

## 막힌 것과 해결

- 변환기가 처음에 `imagecodecs_jpeg` 압축을 모른다며 멈췄다 → 석사형 data.py 처럼 `register_codecs()` 를 먼저 부름.
- 3차 시험이 처음에 실패: 가상 팔이 출발 자리에 오기 전에 재서 속도 제한에 걸린 고른 움직임만 보였다 → 출발 자리에 온 뒤 잼.
- 가짜 노트북 시험을 기다리려고 쓴 `pgrep -f` 반복이 명령 자신의 글자에 걸려 끝나지 않았다 (11/22 메모리에 적어 둔 함정 그대로) → 그 작업만 멈추고, 다시 돌릴 때는 PID 로 `wait`.
