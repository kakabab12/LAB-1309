# 2026-09-14 — 첫 태스크 전환 실험 (LIBERO-Goal + SmolVLA)

> **한 줄 요약**: 지시를 도중에 바꾸면 SmolVLA는 알아듣고도 수행을 못 한다. 원인은 chunk 처리 방식이 아니라 **전환 순간의 로봇 자세**.

## 목표

- LIBERO-Goal 기준 점수 측정
- 첫 전환 실험 (LAB05 7단계): 태스크 A 도중 B로 전환 → B 완료 후 **A 재개**가 되는가

## 한 일

- 연구실 PC(GTX 1080 Ti)에 LeRobot 0.4.4 + hf-libero 환경 구성, SmolVLA LIBERO 체크포인트 실행
- LIBERO-Goal 10개 태스크 × 10 에피소드 기준 점수 측정 → **평균 74%**
- 전환 실험 스크립트 작성: 환경 리셋 없이 지시만 교체, B 성공은 B의 BDDL goal을 같은 시뮬레이션에서 판정
- 전략 4개(flush / keep / blend / retreat) × 전환 시점 3개(접근 중 / 잡은 직후 / 들고 이동 중) × 태스크 쌍 4개 × 10회 = **600 에피소드**
- 결론 검증용 확인 실험 3개 (step 1·5 전환, `n_action_steps=1`, A 재개 영상 확인)
- 상세 보고서: [04_실습/05_libero/switch_experiment](../04_실습/05_libero/switch_experiment/README.md)

## 알게 된 것

- **남은 chunk를 버리든(flush) 끝까지 쓰든(keep) 섞든(blend) B 성공률은 18~39%로 비슷.** 신뢰구간이 모두 겹침
- **"물체 내려놓고 시작 자세로 돌아간 뒤 전환(retreat)"만 B 82~92%, A 재개 50~72%.** 나머지 전략은 A 재개 0~3%
- 원인은 **전환 순간의 로봇 자세**. step 1·5에서 바꾸면 flush도 B 70~100%인데, step 15만 돼도 20~40%로 떨어짐
- SmolVLA는 새 지시를 **알아듣긴 함**(B 대상으로 이동). 낯선 자세(틀어진 손목)에서 **수행을 못 함** → 자동 분류상 "지시 무시"는 0건, 실패는 전부 "시간 초과"
- 매 스텝 재추론(`n_action_steps=1`)해도 해결 안 됨(25% vs 28%). 오히려 저크가 약 2배
- 연구주제.md에서 "잡은 직후"를 핵심 난이도로 봤는데, 이 설정에서는 **접근 중 전환도 똑같이 어려웠음** (flush 18% vs 25%)
- LAB03에서 블렌딩이 저크를 9배 줄였던 것과 달리, 실제 시뮬레이션에서 blend의 저크 감소는 작음
- 반응 시간은 같은 에피소드의 "전환 안 함" 궤적과 비교하면 깔끔하게 잴 수 있음 (전환 전까지 궤적이 완전히 동일)

## 막힌 것 / 해결 방법

| 문제 | 원인 | 해결 |
|---|---|---|
| LeRobot main 설치 불가 | main 브랜치가 Python ≥ 3.12 요구 | Python 3.10 + **LeRobot 0.4.4** 사용 |
| 1080 Ti에서 PyTorch 버전 | 문서엔 2.7.1 권장 | **2.10.0+cu126도 정상 동작** 확인 (cu126 빌드는 Pascal 지원) |
| evdev, egl-probe 의존성 | LIBERO 실행에는 불필요한 패키지 | uv override로 설치에서 제외 (`sys_platform == 'never'`) |
| 물체를 쥔 채 전환하면 B 대신 A를 마저 함 (초기 테스트 1회 관찰) | 정책이 지시보다 현재 시각 상태를 따르는 것으로 추정 | retreat 전략 추가 → 600회 실험에서 "B 중 A 완료"는 flush/keep/blend 0건, 진짜 문제는 자세였음 |
| 방향 변화 기반 반응 시간이 전환 안 해도 튐 | 잡은 뒤 들어올릴 때 원래 방향이 바뀜 | "전환 안 함" 궤적과 2cm 벌어지는 시점으로 재정의 |
| flush A 재개 0%가 버그인지 | - | step 5 전환(B 100% 성공) 후에도 0/20, 영상 확인 → 실제 현상 |
| 이 PC에 git 없음 | - | `git`, `gh` 설치 후 `gh auth login` |
