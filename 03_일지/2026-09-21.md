## 1. ⭐⭐ 물체를 쥐면 정책이 지시문에 귀를 닫는다

**CMI**(조건부 상호정보량)는 *지시문이 동작을 얼마나 가르는가*를 재는 값입니다.
같은 상태에서 지시문만 바꿔 동작이 얼마나 달라지는지를 정보량으로 나타냅니다.
0 에 가까우면 **무슨 지시를 하든 같은 동작**을 한다는 뜻입니다.

| 측정 지점 | CMI (nats) | 뜻 |
|---|---|---|
| 에피소드 시작 | **0.719** | 지시문이 동작을 잘 가른다 |
| **물체를 쥔 직후** | **0.284** | **−61%. 지시문의 영향력이 크게 준다** |
| 들고 이동 중 | **0.761** | 회복된다 |

태스크 4개 모두 같은 패턴입니다.

| 태스크 | 시작 | 쥔 직후 | 이동 중 |
|---|---|---|---|
| T1 | 0.707 | 0.253 | 0.781 |
| T2 | 0.715 | 0.414 | 0.713 |
| T4 | 0.708 | 0.247 | 0.844 |
| T8 | 0.747 | 0.299 | 0.677 |

### 행동으로도 같은 방향이 보인다

| 전환 시점 | CMI | B 성공률 (원본, flush) |
|---|---|---|
| 잡은 직후 | 0.284 (낮음) | **25%** (9/36) |
| 들고 이동 중 | 0.761 (회복) | **39%** (14/36) |

(p=0.156 — 방향은 맞지만 36회씩으로는 유의하지 않습니다. CMI 자체는 직접 측정값이라 별개입니다.)

### 이것이 지금까지의 실패를 전부 설명한다

우리는 계속 **엉뚱한 곳**을 고치고 있었습니다.

| 고치려 한 곳 | 결과 |
|---|---|
| 팔 자세 (LoRA 1·2·3차) | 32 → 32 → 31 → 30% (변화 없음) |
| 생성 노이즈 (시드·CEM) | 처음 보는 쌍 7%, CEM −10%p |
| 전환 후 회복 (흔들기·rollback) | 전부 실패 |

**결함은 지시문 채널에 있었습니다.** 팔이 어디 있든, 노이즈가 무엇이든,
지시문이 동작에 영향을 못 주면 새 지시를 따를 수가 없습니다.

> 📚 CMI 로 조종 가능성을 재는 방법은 [ReSteer](../02_논문노트/ReSteer.md) (2026-03) 에서 가져왔습니다.
> 그 논문은 LIBERO-Goal 에서 π0.5 0.403 / OpenVLA-OFT 0.252 / MolmoACT 0.295 를 보고했고
> **SmolVLA 는 재지 않았습니다.** 우리가 그 자리를 채웠고, 더 나아가
> **조작 단계별로 CMI 가 어떻게 변하는지**를 쟀습니다 — 이건 그 논문에도 없습니다.

## 2. ❌ 노이즈 방향이 닫혔다 — 그리고 제가 성급했던 지점

금요일에 CEM(노이즈 평균 이동 μ 최적화)이 **8→7 에서 50 → 80%** 로 보였습니다.
그때 제가 "p=0.175 라 아직 유의하지 않다"고 적어 뒀는데, 그 경고가 맞았습니다.

| 쌍 (검증용, 학습에 안 쓴 에피소드) | 기준 | μ 적용 | 변화 |
|---|---|---|---|
| 8→7 (ep 10~19) | 5/10 | 8/10 | +30%p |
| **8→7 (ep 20~39, 더 큰 표본)** | **13/20** | **9/20** | **−20%p** |
| 6→0 (ep 10~19) | 4/10 | 4/10 | 0 |
| 4→7 (ep 10~19) | 5/10 | 1/10 | −40%p |
| **합계** | **27/50** | **22/50** | **−10%p** |

μ 가 더 낫다는 검정: **p = 0.885** (근거 없음).

**무엇이 문제였나**: 주말 큐가 CEM 결과를 자동으로 판정해 다음 단계를 고르게 해 뒀는데,
그 판정이 **점추정만 보고** `cem_works` 로 넘어갔습니다. 유의성을 조건에 넣었어야 했습니다.
덕분에 주말 시간을 닫힌 길에 썼습니다 — 다만 그 덕에 **확실하게 닫을 수 있었습니다.**

### 노이즈 방향 전체 정리 (이제 완전히 닫힘)

```
노이즈가 결과를 크게 가르는가?           → ✅ 그렇다 (오라클 47% → 100%, 시드 간 80%p 차이, p<0.001)
그러면 좋은 노이즈를 고르면 되는가?
   ① 좋은 시드를 고정한다               → ❌ 처음 보는 쌍에서 7% (기준 31%, p=0.031)
   ② 평균 이동 μ 를 학습한다 (CEM)       → ❌ −10%p (p=0.885)
   ③ 후보를 판정기로 고른다              → ❌ Q−V = 0.0003, bon 34% ≈ flush 32%
   ④ 노이즈 크기를 바꾼다 (σ=0.5~2.0)    → ❌ σ=2.0 에서 전부 0%
```

**결론**: 좋은 노이즈는 노이즈의 성질이 아니라 **(상태, 노이즈) 짝의 성질**입니다.
상태를 보고 골라야 하는데, 그걸 판정할 수단이 없습니다.

## 4. 회전 30도 = 0% 확정, 그런데 위치를 더하면 살아난다

금요일에 보류했던 것을 20회로 다시 쟀습니다.

| 조건 | 결과 |
|---|---|
| **회전 30도 단독** | **0/20 = 0%** ← 재측정으로 확정 |
| 16cm + 30도 | 2/10 = 20% |
| **20cm + 30도** | **3/7 = 43%** |
| 25cm + 45도 | 0/8 = 0% |

**모순이 아니라 진짜 현상이었습니다.** 같은 30도인데, 팔을 옆으로 20cm 옮겨 주면 43% 가 됩니다.

### 왜 그럴까 (가설)

```
회전만 주면:   팔이 제자리에 있다  →  정책이 "다 왔다" 고 보고 바로 집으려 한다
                                    →  **손목을 고칠 기회가 없다**  →  실패

위치도 주면:   팔이 멀리 있다      →  정책이 이동해야 한다
                                    →  **이동하는 동안 손목이 제자리를 찾는다**  →  성공
```

**정책은 손목 방향을 "이동하면서" 고칩니다. 고칠 거리가 없으면 못 고칩니다.**

⏳ 검증 방법: 궤적에서 손목 회전이 시간에 따라 어떻게 변하는지 보면 됩니다
(`eef_rotvec` 이 기록되므로 바로 잴 수 있습니다). 다음 근무일에 확인합니다.

## 5. ✅ 새 방법 — 지시문 증폭 (instruction CFG)

CMI 가 떨어지는 것이 문제라면, **지시문 채널을 직접 키우면** 됩니다.

흐름 매칭의 속도장을 두 지시문으로 각각 구해서 바깥으로 외삽합니다.

```
v = v_B + (w − 1) · (v_B − v_A)          [ = v_A + w(v_B − v_A) ]

  v_A : 이전 지시(A)로 구한 속도장   ← 음의 조건
  v_B : 새 지시(B)로 구한 속도장     ← 양의 조건
  w   : 증폭 계수 (w=1 이면 원래 정책과 완전히 같다)
```

**핵심은 이전 지시 A 를 음의 조건으로 쓰는 것입니다.**
보통의 CFG 는 "빈 조건"을 음의 조건으로 쓰는데,
**전환 문제에서는 버려야 할 지시가 무엇인지 우리가 정확히 알고 있습니다.** 그 정보를 쓰는 겁니다.

### 제약을 지키는가

| 제약 | 지키나 |
|---|---|
| 초기 자세로 복귀 금지 | ✅ 자세를 전혀 건드리지 않습니다 |
| 사람처럼 자연스럽게 | ✅ 스크립트 동작이 없습니다. 정책이 뽑은 동작 그대로입니다 |
| 학습 없이 | ✅ 추론만 바꿉니다 |

### 구현을 믿을 수 있는지 먼저 확인했다

w=1 이면 수식상 원래 정책과 같아야 합니다. 안 같으면 버그입니다.

| 비교 | 최대 차이 |
|---|---|
| 원본 vs 원본 (재현성 바닥) | 0.000 |
| 원본 vs w=1 (**처음 구현**) | 3.8e-3 ← ❌ |
| 원본 vs w=1 (**수식 정리 후**) | **0.000** ← ✅ |

처음엔 `v_A + w(v_B − v_A)` 로 썼는데 **큰 값끼리 빼고 더하는 상쇄 오차**가 생겼고,
적분 10스텝을 지나며 0.5% 까지 커졌습니다.
`v_B + (w−1)(v_B − v_A)` 로 바꾸니 w=1 에서 오차가 정확히 0 이 됩니다.

> 이걸 먼저 확인하지 않았다면, 나중에 나오는 차이가 **방법의 효과인지 버그인지** 구분할 수 없었을 겁니다.

### w 를 키우면 동작이 얼마나 달라지나

| w | 동작 크기 (정규화 공간) |
|---|---|
| 1.0 | 0.686 |
| 1.5 | 0.887 |
| 2.0 | 1.106 |
| 3.0 | 1.438 |
| 5.0 | 1.687 |

정규화 동작이 1.0 을 넘으면 포화를 의심해야 하므로, **w=1.5~2.0 근처가 후보**입니다.

⏳ 지금 평가 중입니다 (4쌍 × w 3개 × 10회 = 120 에피소드).

## 막힌 것 / 해결 방법

| 문제 | 원인 | 해결 |
|---|---|---|
| 주말 큐가 닫힌 길로 진행 | CEM 자동 판정이 **점추정만** 봄 (p=0.175 무시) | 자동 판정에는 **유의성 조건**을 넣어야 함 |
| w=1 이 원본과 미세하게 다름 | `v_A + w(v_B−v_A)` 의 **상쇄 오차**가 적분으로 증폭 | `v_B + (w−1)(v_B−v_A)` 로 재작성 → 오차 0 |
| A 재개 통제 실험(스텝 600)이 죽음 | `max_steps 600` × 3구간이 robosuite horizon(1000) 초과 | 이미 회전 분석으로 답을 얻어 재실행 불필요 |
| 30도 단독 0% 와 조합 43% 가 충돌 | 측정 오류가 아니라 **진짜 현상** | 20회 재측정으로 확정, 새 가설(이동 중 회전 보정) 수립 |
