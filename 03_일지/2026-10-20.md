# 2026-10-20 '쥐는 높이에서 손을 올리는' 버릇은 교정 시범에서 왔다

> 한 줄 요약: 남은 가장 큰 실패(블록 위에서 못 쥠)의 출처를 데이터에서 찾았다 — 교정·회복 시범에서 시범 프로그램이 블록 바로 위에서 넘겨받아도 늘 8cm 위로 먼저 올라갔다. 시범 프로그램을 고쳐 교정 시범을 다시 모으고, 올라가는 시범 111개를 빼고 학습한다.

## 1. 버릇의 출처

10/17 에 '블록 위에서 못 쥠' 장면을 다시 돌려 보니, 손이 쥐는 높이에 오면 학생이 그리퍼를 벌린 채 위로 +1.0 을 명령했다. 쥐기를 규칙으로 해 줘도 그 뒤 들어 올리지 않았다.
학생이 이런 동작을 어디서 배웠나 보려고 시범을 하나씩 셌다.

- 교정 시범(DAgger)은 학생이 돌다가 아무 때나 시범 프로그램이 넘겨받는다. 시범 프로그램(`_grasp_bowl_piper`, align 방식)은 어디서 넘겨받든 '블록 위 8cm 로 → 똑바로 내려감' 순서로 쥔다
- 그래서 학생이 블록 바로 위 낮은 곳에서 머뭇거리던 장면을 넘겨받아도 먼저 위로 올라갔다. 예) DN2_ep3415: 블록에서 0.6cm, 쥐는 높이 0.6cm 위에서 넘겨받아 6.9cm 올라감
- 빈손으로 블록 3cm·쥐는 높이 6cm 안에서 넘겨받은 75개 중 63개 (84%)
- 학생에게는 '블록 바로 위 낮은 곳 → 위로' 가 정답으로 들어간 셈이다. 남은 실패와 꼭 같은 모습이다 (가설: 이것이 원인)
- 어제까지 보조를 켠 채 모은 교정 시범(als2a)은 학생이 블록 위에서 머뭇거리는 장면을 더 많이 넘겨받아, 111개 중 30개가 이 모양이었다. als3a 가 오르지 않은 이유일 수 있다

## 2. 고친 것

- 시범 프로그램 (`task_experts._near_grasp`, `PIPER_NEAR_GRASP=1` 일 때만): 빈손이고 손이 쥐는 점에서 옆 1.5cm·위 8cm 안이며 지금 손 방향과 20° 안의 쥐는 방향이 있으면(손가락이 대칭이라 180° 돌린 방향도 같은 쥐기로 봄), 그 높이에서 맞추고 → 천천히 내려가 → 3~6스텝 멈춤 → 오므림 → 10cm 들어 올림. 아니면 원래 방식. 처음에는 180° 대칭을 안 봐서 한 번도 켜지지 않았다
- 학습에서 빼기 (`find_rise.py`, `train_lora.py --exclude`): 빈손으로 블록 바로 위(옆 2cm·위 6cm 안)에서 쥐지 않고 40스텝 안에 3cm 넘게 올라가는 시범 111개

## 3. 순서 (`run_near_round.sh`, 13시 50분~)

als2 + 보조 켠 교정 시범 (고친 시범 프로그램, 0.75 규모) → 새 시범도 다시 거름 → als3b 학습 (als2 에서, 올라가는 시범 뺌) → als3b + 보조 28항목 → als3b 단독 28항목. 비교 기준은 als3a (같은 출발점, 고치기 전 교정 시범).

## 4. 받침대 없이 (사용자 결정, 16시)

사용자가 PiPER 밑의 검은 기둥이 무엇인지 물었다. 10/3 부엌 장면(LIBERO-Goal: 캐비닛 손잡이·윗면이 책상 위 19~23cm, 와인 선반) 때 팔이 짧은 PiPER(어깨~손목 최대 54cm)가 캐비닛 손잡이에 손가락을 걸 수 있게 올린 29cm 받침대다. 블록 장면으로 바꾼 뒤에도 그대로 남아 있었다. 사용자는 받침대 없이 책상 위에 바로 두기로 했다.

받침대 높이별로 블록·판 64개 점(넓은 배치의 네 모서리 × 쥐기·8cm 위·12cm 위·놓기)에 그리퍼를 똑바로 아래로 향한 채 닿는지 (`piper_sim/reach_blocks.py`, 역기구학, 위치 1cm·방향 5° 안):

| 받침대 | 닿지 않음 | 관절 여유 중앙 |
|---|---|---|
| 0cm (밑동 x −0.38 / −0.33) | 21 / 16 | 8° / 7° |
| 10cm | 2 | 22~25° |
| 15cm (x −0.33) | 0 | 32° |
| 29cm (지금) | 2~4 | 21~23° |

받침대 없이는 손목 5번 관절(±70°) 때문에 책상 위 10cm 넘는 곳에서 그리퍼를 똑바로 아래로 둘 수 없다 (블록 위 8cm 에서 똑바로 내려가는 지금 시범 방식이 안 됨). 그리퍼를 15~30° 기울이면 닿는다 (±15° 까지 허용하면 64개 중 63개). 15cm 가 가장 여유가 크다고 알렸고, 사용자는 받침대 없음을 골랐다.

- `PIPER_NOPED=1` 이면 받침대 없는 배치 (`layout_noped.json`: 밑동 (−0.33, 0, 책상 높이), `assets/robots/piper_noped/robot.xml`, `init_qpos_noped.json`). 기본은 그대로라 돌고 있는 als3b 학습·평가는 영향 없음
- 처음 자세: Panda 처음 자세 근처(책상 위 28cm, 밑동 앞 12cm)는 닿지 않아, 앞으로 기울인 방향까지 넣어 다시 찾는 중 (`calib_home.py`)
- 다음: 기울인 손으로 시범 프로그램이 블록을 쥐는지 확인 → 시범 전부 새로 모으기 → 사진 특징 → 학습 → 평가 (하루쯤)

## 5. 받침대 없는 배치 준비 (17시)

사용자: "앞으로 바침대 없이해줘". 받침대 실험(als3b)은 학습만 마치고 '블록 위에서 못 쥠' 이 많던 6항목만 잰다 (`run_near_eval.sh`).

- 처음 자세 (`calib_home.py`, `init_qpos_noped.json`): Panda 처음 자세 근처(책상 위 28cm·밑동 앞 12cm)는 받침대 없이 닿지 않는다. 앞으로 기울인 방향까지 넣어 찾으니 책상 위 14cm·빨간 블록 바로 위가 관절 여유가 가장 컸지만, '처음 자세 7cm 안으로 돌아오면 실패' 규칙에 걸릴 수 있어 블록과 떨어진 **책상 위 18cm·밑동 앞 18cm·앞으로 45° 기울임** (관절 여유 21.6°, 빨간 블록 윗면까지 14.8cm) 으로 정했다
- 쥐는 방향 (`task_experts`, NOPED): 처음 자세가 기울어 있어 후보를 '똑바로 아래' 기준에서 만들고, 기울기를 ±35° 까지 넓혀 역기구학으로 닿는 것을 고른다
- 노란 막대: 기울인 손으로 높이 4cm 막대를 2cm 에서 쥐면 아래쪽 손가락이 책상을 0.1~1cm 파고들어 후보가 모두 빠졌다 (T2·T7 0/3). 쥐는 높이 2.8cm 로 → 5/5. 실행 보조의 막대 쥐는 높이도 같이
- 시범 프로그램 시험: 과제 10개 (3장면씩, 막대는 5장면) 모두 성공. 일 바꾸기 6쌍 × 3장면 — 원래 일·새 지시·돌아오기 모두 저장



순서 (`run_np_round.sh`, 17:26~): 시범 전부 새로 (정상 600, 넓은 600, 일 바꾸기 12쌍 × 40, 회복 300 — 회복은 고친 시범 프로그램) → 다듬기·검출·손 기준 위치 → 올라가는 시범 거르기 → 사진 특징 → np1 학습 (als2 에서, 동작 정규화 다시, 15,000스텝) → np1 + 보조 28항목 → np1 단독 28항목. 내일 오후쯤 첫 성적.
