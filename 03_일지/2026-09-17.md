# 2026-09-17 — retreat ablation + LoRA 1차 학습 (실패 분석)

> **한 줄 요약**: 초기 위치로 되돌리면 전환이 잘 되지만, 실제 전환에서 팔 위치로는 성공이 안 갈렸다. 학습 없는 전략 rtc(18%)·bon(34%)도 flush(32%)를 못 넘었고, LoRA 1차는 데이터 편향으로 실패했다.

## 이 일지에서 새로 나오는 말

| 말 | 뜻 |
|---|---|
| **rtc** | 새 동작을 이전 동작에 이어지게 만드는 전환 방식 (Real-Time Chunking) |
| **bon (Best-of-N)** | 동작 후보 N개를 뽑아 점수가 가장 좋은 것을 실행 |
| **짝 비교 / 부호 검정** | 같은 에피소드에서 두 방법을 비교해, 한쪽만 성공한 횟수로 차이가 우연인지 판단 |
| **ablation** | 방법의 요소를 하나씩 빼서 뭐가 효과를 내는지 보는 실험 |
| **ret_pos / ret_rot / release** | retreat 을 쪼갠 것. 위치만 복구 / 손목 회전만 복구 / 내려놓기만 |
| **LoRA** | 모델 가중치는 얼리고 작은 행렬만 붙여 학습. 우리는 전체의 0.81%만 학습 |
| **self-imitation** | 모델이 스스로 성공한 궤적만 모아 다시 학습 |
| **hindsight relabeling** | B 에 실패했어도 우연히 해낸 다른 태스크 C 로 이름표를 바꿔 학습 데이터로 씀 |
| **망각** | 새로 배우다 원래 잘하던 걸 못하게 되는 것 |
| **균형 샘플링** | 태스크마다 뽑힐 확률을 같게 맞추는 것 |

전체 용어는 [용어사전](../용어사전.md).

## 알게 된 것

### 1. 핵심은 위치 복구

![ablation](../04_실습/05_libero/retreat_ablation/results/ablation.png)

| 전략 | B 성공 | A 재개 |
|---|---|---|
| 그 자리에서 교체 (flush) | 32% | 1% |
| 내려놓기만 (release) | **8%** | 3% |
| 회전만 복구 (ret_rot) | **12%** | 4% |
| 위치만 복구 (ret_pos) | **64%** | 16% |
| 위치 + 회전 (retreat) | **89%** | 61% |

![위치 복구 vs 회전 복구](../04_실습/05_libero/retreat_ablation/results/ablation_pos_vs_rot.gif)

*같은 에피소드: 왼쪽 위치만 복구 → 성공, 오른쪽 회전만 복구 → 실패*

- 회전만 고치면 거의 효과 없음, **위치가 대부분을 설명**
- **내려놓기만 하면 오히려 더 나빠짐** — 테이블 근처 낮은 곳에 팔이 머물러 더 낯선 상태가 됨
- 9/16엔 회전이 더 치명적이었는데 모순이 아니었다. 전환 순간 팔이 초기 자세에서 **12~27cm** 떨어져 있었고, 9/16 측정 범위는 10cm까지였다. **실제 전환에서는 위치 이탈이 훨씬 크다**

### 2. LoRA 1차는 실패, 원인은 데이터

![전환 전후](../04_실습/05_libero/lora_v1/results/lora_v1_switch.png)

- 전환 성공률 **32% → 32%** (잡은 직후는 오르고, 들고 이동 중은 내림)
- 1→5, 2→5 는 원래 0~17%라 성공 데이터가 **0개** → 전혀 못 배움. **self-imitation 은 못하는 걸 가르칠 수 없다**
- "turn on the stove" 가 학습 데이터의 **40%** → 같은 스토브 근처의 "put the bowl on the stove" 가 100% → 60% 로 망가짐

![원본 vs LoRA](../04_실습/05_libero/lora_v1/results/lora_v1_base_vs_lora.gif)

*LoRA 가 나아진 에피소드 예시 (4→7, 그 자리에서 전환): 왼쪽 원본 실패, 오른쪽 LoRA 1차 성공. 전체 합계는 변화 없음*

![태스크 1](../04_실습/05_libero/lora_v1/results/lora_v1_pose_task1.png)

### 3. 그래도 학습 자체는 정상

![학습 곡선](../04_실습/05_libero/lora_v1/results/lora_v1_curve.png)

검증 loss 가 안정적이었고, 데이터가 있던 "잡은 직후" 전환은 50→70%, 30→60% 로 올랐다. **데이터만 맞으면 학습이 먹힌다.**

### 4. 자연스러움을 숫자로 — 원위치 방식은 38cm 더 돌아간다

![자연스러움](../04_실습/05_libero/naturalness/results/naturalness.png)

| 전략 | 경로 길이 | 우회 비율 | 소요 시간 | 멈춤 |
|---|---|---|---|---|
| flush | 67cm | 1.52 | 7.7초 | 1 |
| retreat (원위치) | **105cm** | **2.45** | 9.0초 | **2** |
| LoRA 1차 flush | **63cm** | **1.45** | 8.0초 | 1 |

- **성공률과 자연스러움이 반대로 간다.** retreat 은 가장 잘 되지만 가장 돌아간다 → 리셋 금지 제약이 필요한 이유
- **LoRA 1차가 가장 곧다.** 성공률은 못 올렸지만, 리셋 없는 데이터로 배워서 돌아가지 않고 바로 간다
- 우회 비율 = 이동 거리 ÷ 직선 거리. 멈춤 = 0.25초 이상 거의 정지. 자세한 정의는 [보고서](../04_실습/05_libero/naturalness/README.md)

### 5. ⚠️ 가설 검증: 팔 위치로는 성공이 안 갈린다 (앞선 해석 수정)

"전환 순간 팔이 멀어서 실패한다"를 에피소드 112개로 직접 확인했더니 **틀렸습니다.**

![거리 비교](../04_실습/05_libero/hypothesis_check/results/manifold_distance_vs_success.png)

| 거리 기준 | 성공과의 상관 |
|---|---|
| 초기 자세와의 거리 | r = +0.14 (오히려 멀수록 약간 더 성공) |
| B 정상 경로와의 거리 | r = +0.23, 쌍마다 방향이 제각각 |

- **장면(초기 배치)은 성공 차이의 16~31% 만 설명**. 나머지는 같은 장면에서도 **시도마다 결과가 바뀌는 무작위성**
- 앞선 결론 수정: "위치가 멀어서" 가 아니라, "초기 자세로 되돌리면 좋아진다(ablation)"까지만 사실. 되돌리기는 위치 말고도 **물체 내려놓기·멈추기·장면 정리** 효과가 섞여 있음
- **다음 방향이 바뀜**: 팔 위치 거리로 고르는 `bon` 은 약할 것으로 예상. 무작위성이 크다는 건 **좋은 후보와 나쁜 후보가 섞여 나온다**는 뜻이라, **학습한 판정기로 고르기**([V-GPS](../02_논문노트/V-GPS.md), [Q-Planning](../02_논문노트/Q-Planning.md))나 **노이즈 조종**([DSRL](../02_논문노트/DSRL.md))이 유망
- 자세한 분석: [가설 검증 보고서](../04_실습/05_libero/hypothesis_check/README.md)

### 6. 학습 없는 전환 전략 두 가지 — 둘 다 flush 를 넘지 못했다

LoRA 처럼 모델을 바꾸지 않고, **추론할 때만** 전환을 돕는 방법 두 가지를 논문에서 가져와 시험했습니다.

![학습 없는 전략](../04_실습/05_libero/training_free/results/training_free_strategies.png)

| 전략 | 방식 | 참고 논문 | B 성공 | A 재개 | 우회 비율 |
|---|---|---|---|---|---|
| flush | 남은 동작 버리고 즉시 새 지시 | - | 32% (23/72) | 1% | 1.52 |
| **rtc** | 새 동작을 이전 동작에 이어지게 생성 | [Real-Time Chunking](../02_논문노트/Real-Time-Chunking.md) | **18%** (13/72) | 8% | **2.32** |
| **bon** | 후보 8개 중 성공 궤적 근처로 가는 것 선택 | [Q-Planning](../02_논문노트/Q-Planning.md), [V-GPS](../02_논문노트/V-GPS.md), [RoboMonkey](../02_논문노트/RoboMonkey.md) | **34%** (25/73) | 0% | **1.47** |
| retreat (진단) | 초기 자세 복귀 | [SwitchVLA](../02_논문노트/SwitchVLA.md) | 89% | 61% | 2.45 |

**rtc — 매끄럽지만 틀린 방향으로 갔다**
- 저크는 9.6 → **6.0** 으로 가장 부드러움. 하지만 성공률은 오히려 떨어짐
- 전략 중 유일하게 **지시 무시(B 도중 A 를 끝냄) 4회**, 전환 직후 **되돌아감 1.8cm** 로 가장 큼
- 이유: 새 동작을 **A 를 하던 방향에 맞춰** 만들어서, 들고 이동 중일 때(70% → 20%) 특히 A 쪽으로 끌려감
- 교훈: **"매끄럽다 ≠ 자연스럽다."** 사람도 일을 바꿀 때는 하던 동작을 끊음 → 후속 실험 `flush_rtc`(전환 순간 끊고, 그 뒤부터 이어붙이기) 진행 중

**bon — 가장 곧게 가지만 성공률은 같다**
- 같은 에피소드끼리 짝 비교: bon 만 성공 **10**, flush 만 성공 **8**, 같음 54 → **부호 검정 p ≈ 0.82, 차이 없음**
- 잡은 직후(8→7 50→70%, 4→7 30→70%)는 올랐지만 들고 이동 중(4→7 70→40%)은 내려 상쇄
- **5번 가설 검증의 예측대로**: 팔 위치 거리는 성공과 무관 → 그걸 점수로 쓴 선택도 무의미
- 후보들이 실제로 다르긴 함(20스텝 뒤 위치가 약 5cm 퍼짐) → **고를 거리는 있는데 고르는 기준이 틀렸다** → 다음은 **학습한 판정기**

### 7. ⚠️ 사고: LoRA 2차가 데이터가 빠진 채 학습됨

- `switch_experiment.py` 에 새 옵션(rtc·bon·판정기 기록)을 추가하는 사이, 그 파일을 불러 쓰는 `collect_robust_data.py` 는 **옛 옵션만 넘기고 있어서** 수집 작업이 시작하자마자 죽음
- 결과: 먼 교란 7개 중 4개, hindsight 8개 **전부** 데이터 0개. 그런데 파이프라인은 멈추지 않고 **있는 데이터로 학습·평가까지 진행**
- 해결: 빠진 옵션을 기본값으로 채우는 `fill_defaults()` 추가, 이 파일을 쓰는 스크립트 4개 모두 재실행해 확인. 잘못 학습된 모델은 `lora_v2_partial` 로 보관하고 **빠진 부분만 다시 수집해 재학습 중**
- 교훈: **돌고 있는 파이프라인이 쓰는 코드를 고치지 말 것.** 그리고 수집 단계에서 저장 개수가 0이면 **멈추게** 해야 함

| 문제 | 원인 | 해결 |

| 학습 중 저장하면 LoRA 가 풀림 | `merge_and_unload` 가 LoRA 를 제거하고 옵티마이저 참조가 끊김 | 학습 중엔 어댑터만 저장, 끝나고 따로 합치기 |
| forward 가 패딩 마스크를 못 읽음 | SmolVLA 가 읽는 키 이름이 `actions_id_pad` (오타 같은 이름) | 그 이름으로 넣음 |
| 1→5, 2→5 성공 데이터 0개 | 원래 성공률이 낮음 | 2차에서 hindsight relabeling |
| hindsight 모드가 태스크 짝을 못 받음 | 조건문이 `switch` 만 확인 | `switch`, `hindsight` 둘 다 처리 |
| **LoRA 2차 수집 작업이 전부 죽음** | 실행 중에 공용 코드에 옵션을 추가 → 옛 옵션만 넘기던 수집 스크립트가 오류 | `fill_defaults()` 로 빠진 옵션 자동 채움, 빠진 부분만 재수집 |
| rtc 가 inference_mode 에서 동작 안 함 | RTC 보정이 자동미분 사용 | 해당 경로만 `no_grad` 로 |
| bon 후보 8개 동시 계산 시 메모리 부족 | 이미지 인코더도 8배 | 2개씩 나눠 계산 (`--bon-batch 2`) |
| MuJoCo 수집 중 EGL 오류 로그 | 에피소드 종료 시 렌더러 정리 경고 | 결과에 영향 없음 (수집 통계 정상) |
