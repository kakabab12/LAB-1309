# 02 실제 시스템 정리 (2026-10-06)

출처: 포트폴리오 저장소 `kakabab12/My_portfolio` → `2026/03. 캡스톤 - 스마트팩토리 비전검사`, 사용자 설명, 시연 영상(로봇팔 제외), MakerWorld 컨베이어 모델.

## 공정 흐름

```
컨베이어(색 분류) ─ 빨강·초록 큐브 → 불량 통
        └ 파랑 큐브 → 저울 위 파란 통
저울 7-segment ─ 카메라 → YOLOv8 숫자 인식 → 무게
   무게 ≥ 118g → MCP 트리거("run") → SO-101 + ACT 가 통을 적재 (1층 → 옆 → 2층)
   저울이 비면  → 로봇팔이 빈 파란 통을 저울에 올림 → 반복
```

## ACT 실행기 (`run_act_inference_jetson_fixed.py`, 1702줄)

| 기능 | 내용 |
|---|---|
| 트리거 | MCP TCP 서버 `0.0.0.0:8765`, `run/start/stack/trigger` → 실행, `reset/restart` → 카운터 초기화 (JSON 또는 텍스트) |
| 상태 | `WAIT → RUNNING → RETURN_HOME → (다음 WAIT) … → DONE` (`--max-runs 3`) |
| 바쁜 동안 | 들어온 트리거는 무시하고 응답 (`drain_pending_triggers`) |
| 복귀 | 시작 때 관절값을 홈으로 저장, 실행 뒤 30회 반복 명령 |
| Jetson 최적화 | 스레드 1개 제한, `CUDA_MODULE_LOADING=LAZY`, AMP, 정규화 버퍼 복구(구버전 체크포인트 대응) |
| 안전 | `--action-scale`, `--max-relative-target`, `--dry-run` |

주의: LeRobot ACT 는 **작업 문장(task)을 입력으로 쓰지 않는다.** 코드의 `"stack blue box on floor 1"` 같은 문자열은 정책에 영향이 없다. 그래서 단계마다 모델을 따로 두는 팀의 방식이 맞다.

## ACT 가 하는 일

리더암·팔로워암은 **시연을 모으는 방법**이고, ACT 는 그 시연으로 학습하는 **모델**이다.
실행할 때 ACT 는 손목·위쪽 카메라 영상과 현재 관절값을 받아, 앞으로 100스텝(약 3.3초) 분량의 관절 목표값을 한 번에 낸다.
통을 따로 검출하지 않고 ResNet18 이 영상에서 위치를 스스로 익힌다(종단간).
