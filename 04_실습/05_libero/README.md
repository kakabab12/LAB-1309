## 1. 핵심 숫자

### 전환 성공률 (B 를 해내는가)

4개 태스크 쌍(8→7, 4→7, 1→5, 2→5) × 2개 전환 시점 × 10회, 초기상태 고정.

| 전략 | 리셋? | 잡은 직후 | 들고 이동 중 | 합계 |
|---|---|---|---|---|
| `flush` (그 자리) | ✗ | 25% (9/36) | 39% (14/36) | **32%** (23/72) |
| `keep` | ✗ | 25% (9/36) | 33% (12/36) | 29% (21/72) |
| `blend` | ✗ | 28% (10/36) | 22% (8/36) | 25% (18/72) |
| `rtc` | ✗ | 25% (9/36) | 11% (4/36) | 18% (13/72) |
| `flush_rtc` | ✗ | 28% (10/36) | 6% (2/36) | 17% (12/72) |
| `bon` (후보 8개 중 선택) | ✗ | 41% (15/37) | 28% (10/36) | 34% (25/73) |
| **LoRA 2차** | ✗ | 26% (9/34) | 35% (12/34) | 31% (21/68) |
| `release` (놓기만) | ✗ | 11% (4/36) | 6% (2/36) | 8% (6/72) |
| `ret_rot` (회전만 복귀) | ✅ | 16% (6/37) | 8% (3/37) | 12% (9/74) |
| `ret_pos` (위치만 복귀) | ✅ | 64% (23/36) | 65% (24/37) | 64% (47/73) |
| `retreat` (완전 복귀) | ✅ | 92% (33/36) | 86% (31/36) | 89% (64/72) |

**읽는 법**: ✅ 표시는 **제약 위반**(초기 자세 복귀)이라 최종 방법으로 쓸 수 없습니다. 상한을 보여주는 진단용입니다.
제약을 지키는 것들(✗)은 모두 **30% 근처에 몰려 있습니다.** 이게 우리가 넘어야 하는 벽입니다.

### ⭐ 쌍별로 보면 문제가 두 종류다 (2026-09-18)

| 전략 | 8→7 | 4→7 | **1→5** | **2→5** |
|---|---|---|---|---|
| `flush` | 55% | 50% | 5% | 8% |
| **오라클** (같은 상태에서 8번 다시 뽑기) | **100%** | **100%** | **0%** | **17%** |
| `release` (놓기만) | 10% | 20% | 0% | 0% |
| `ret_pos` (위치만 복귀) | 100% | 100% | 30% | 8% |
| **`retreat`** (위치+손목회전 복귀) | 100% | 100% | **75%** | **75%** |

- **쉬운 쌍**: 상태는 괜찮다 → **다시 뽑기만 해도 100%** (실패는 노이즈 운)
- **어려운 쌍**: 상태가 망가졌다 → 다시 뽑기 0%, 물체만 놓아도 0%, **손목 회전까지 되돌리면 75%**
- → **손목 회전이 결정적** (+45%p). [오라클 보고서](oracle_bon/README.md)에 자세히

### 추론 지연 (저사양 문제)

| 지연 | 태스크 성공 (RTC 끔) | RTC 켬 |
|---|---|---|
| 없음 | 90% | 75% |
| 0.25초 | 72% | 72% |
| **0.56초 = 1080 Ti 실측** | **12%** | **28%** |
| 1초 | 0% | 8% |

**이게 가장 중요한 실측입니다.** 위 전환 성공률 표는 모두 "계산하는 동안 세상이 멈추는" 동기 실행입니다.
실물 로봇에 이 GPU 로 올리면 오른쪽 열이 현실입니다.

### A 재개 (B 를 끝낸 뒤 중단한 A 를 다시 해내는가)

| 전략 | 물체를 어떻게 했나 | A 재개 성공 |
|---|---|---|
| `flush` / `keep` / `blend` / `bon` | 쥔 채 그 자리에서 전환 | **0%** (0/23, 0/21, 0/18, 0/25) |
| `rtc` | 〃 | 8% (1/13) |
| `ret_pos` | 놓고 위치만 복귀 | 9% (4/47) |
| `retreat` | 놓고 완전 복귀 | **62%** (40/64) |

**우리 연구의 두 번째 목표는 아직 전혀 안 풀렸습니다.** 그 자리에서 전환하면 A 의 물체가 B 를 하는 동안
어딘가로 밀려나 A 를 다시 할 수 없게 됩니다. 물체를 원래 자리에 되돌려야 재개가 가능합니다
→ `rollback` 이 **제약을 지키면서 그걸 하는 유일한 후보**입니다.

### 자연스러움 (성공한 경우만, 중앙값)

| 전략 | 경로 길이(cm) | 우회 비율 | 멈춤 횟수 |
|---|---|---|---|
| `flush` | 67.3 | 1.52 | 1.0 |
| **LoRA 2차** | **63.6** | **1.42** | 1.0 |
| `rtc` | 84.2 | 2.32 | 2.0 |
| `ret_pos` | 95.4 | 2.36 | 2.0 |
| `retreat` | 104.7 | 2.45 | 2.0 |

초기 자세로 돌아가는 방식은 **38~41cm 더 돌아갑니다.** "자연스럽게"라는 제약을 수치로 확인한 부분입니다.

## 2. 지금까지 배제한 설명

| 설명 | 어떻게 확인했나 | 결과 |
|---|---|---|
| 전환 시점 팔 위치가 학습 분포에서 멀어서 | 위치 거리 vs 성공 상관 | ❌ r = +0.14 (거의 무관) |
| B 의 정상 경로에서 멀어서 | B 정상 궤적과의 최근접 거리 | ❌ r = +0.23, 단조성 없음 (오히려 먼 쪽이 성공) |
| 후보 동작 중 좋은 걸 못 골라서 | 판정기 학습 (11,563 결정) | ❌ AUC V 0.9318 vs Q 0.9321 (**차이 0.0003**) |
| 남은 chunk 처리 방식 때문에 | flush/keep/blend/rtc 비교 | ❌ 모두 30% 근처 |
| 데이터가 부족해서 | LoRA 1차·2차 (442 에피소드) | ❌ 32% → 31% |
| 물체를 안 놓고 버텨서 (태스크 집착) | B 구간에서 그리퍼가 열리는지 확인 | ❌ **성공·실패 모두 100% 놓음** |
| 엉뚱한 방향으로 가서 | B 정상 궤적 진행도 | ❌ 방향은 맞고 **60~80% 까지 감** |
| 얼어붙어서 | 뒤 100스텝 이동량 | ❌ 계속 움직임 (24.8cm) |
| **좁은 영역에서 왕복해서** | 경로/범위 비율, 쌍 안에서 AUC | ✅ **이게 실패의 모양** ([보고서](failure_mode/README.md)) |
| 장면(태스크 쌍)이 어려워서 | 쌍별 분산 분석 | ⚠️ 16~31% 만 설명 |

**찾은 실패의 모양**: 좁은 영역에서 **왕복**한다 → [실패의 정체](failure_mode/README.md)
**남은 후보 설명**: [ReSteer](../../02_논문노트/ReSteer.md) 의 **"그 상태에서는 지시문이 동작에 영향을 못 준다"**(instruction-blind).
→ `steerability.py` 로 CMI 를 재서 직접 확인 중입니다.
