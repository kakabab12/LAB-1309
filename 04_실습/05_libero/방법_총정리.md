# 방법 총정리 — 전환 전략과 데이터 수집 모드 (논문 출처 포함)

## 📌 쉬운 말 요약

지금까지 시험했거나 만들어 둔 방법을 **한 곳에** 모았습니다. 크게 두 종류입니다.

1. **전환 전략** — 로봇이 일하는 도중 지시가 바뀌었을 때 **그 순간 어떻게 처리할지** (학습 없음)
2. **데이터 수집 모드** — 모델을 다시 학습시키기 위해 **어떤 경험을 모을지** (LoRA 학습용)

모든 방법은 **초기 자세로 돌아가지 않는다**는 제약([연구주제.md](../../연구주제.md))을 기준으로 "최종 방법 후보"와 "진단용"으로 나눴습니다.

## 1. 전환 전략 (`switch_experiment.py --strategy`)

| 전략 | 한 줄 설명 | 리셋? | 역할 | 참고 논문 | 결과 |
|---|---|---|---|---|---|
| `none` | 지시를 안 바꿈 | - | 기준값 | - | - |
| `flush` | 남은 동작 버리고 즉시 새 지시 | ✗ | **후보** | - | B 32% (잡은 직후+이동 중) |
| `keep` | 남은 동작 다 쓰고 새 지시 | ✗ | 후보 | - | 비슷 |
| `blend` | 이전·새 동작 앞부분을 가중평균 | ✗ | 후보 | [RTC](../../02_논문노트/Real-Time-Chunking.md) 의 단순 근사 | 비슷 |
| **`rtc`** | 새 동작을 **만드는 과정에서** 이전 동작에 맞춤 | ✗ | **후보** | [Real-Time Chunking](../../02_논문노트/Real-Time-Chunking.md) (NeurIPS 2025) | **B 18%** ❌ (A 방향으로 끌려감) |
| `flush_rtc` | 전환 순간 끊고, 이후 RTC | ✗ | 후보 | [RTC](../../02_논문노트/Real-Time-Chunking.md) 변형 | **B 17%** ❌ (flush 보다 나쁨, p≈0.05) |
| **`bon`** | 후보 N개 중 **성공 궤적 근처로 가는** 것 선택 (⚠️ [가설 검증](hypothesis_check/README.md)상 위치 거리가 성공과 무관해 효과 약할 것으로 예상) | ✗ | **후보** | [Q-Planning](../../02_논문노트/Q-Planning.md) 축소판, [V-GPS](../../02_논문노트/V-GPS.md), [RoboMonkey](../../02_논문노트/RoboMonkey.md) | **B 34%** (flush 와 차이 없음, p≈0.82) |
| `retreat` | 내려놓고 **초기 자세 복귀** 후 전환 | ✅ | 진단·상한 | [SwitchVLA](../../02_논문노트/SwitchVLA.md) 의 rollback/advance 와 같은 발상 | B 89% |
| `ret_pos` | 내려놓고 **위치만** 복귀 | ✅ | 진단 | ablation | B 64% |
| `ret_rot` | 내려놓고 **회전만** 복귀 | ✅ | 진단 | ablation | B 12% |
| `release` | 내려놓기만 | ✗ | 진단 | ablation | B 8% |
| **`rollback`** | **최근 동작을 거꾸로 재생**해 집었던 자리에 내려놓고 전환 | ✗ **(초기 자세로 안 감)** | 후보 | [SwitchVLA](../../02_논문노트/SwitchVLA.md) 의 rollback 모드 | ❌ **19%** (flush 32%, p=0.064) |
| **`ret_part`** | 초기 자세 쪽으로 **f 만큼만** 되돌리기 (f=0 은 release, f=1 은 retreat) | f 에 따라 | **진단 + 후보** | 용량-반응 설계 | ⏳ 측정 중 |
| **`finish_a`** | **하던 일을 마치고** 넘어가기 (즉시성 포기) | ✗ | **후보** | [SwitchVLA](../../02_논문노트/SwitchVLA.md) 의 late switch 와 비슷 | ⏳ 측정 중 |
| `--dither-escape` | 제자리 맴돌기를 감지하면 흔들어 탈출 (4방향) | 방향에 따라 | 후보 | [PIP](../../02_논문노트/PIP-Policy-Idling.md) | ❌ 4방향 모두 효과 없음 |

### `rollback` 은 왜 제약을 지키나

`retreat` 은 **에피소드 시작 자세**로 P 제어로 돌아갑니다 → 리셋/캘리브레이션이 되어 금지입니다.
`rollback` 은 **최근에 실행한 동작들을 되짚어 갑니다.**

```
지금까지 실행한 동작:  a₁ a₂ … a_g … a_t        (a_g = 그리퍼를 닫은 시점)
rollback 이 실행:      −a_t … −a_g … −a_{g−10}   (순서 뒤집고 부호 바꿈)
                              ↑ 이 시점부터 그리퍼를 연다 = 물체를 그 자리에 놓음
```

- 동작이 **끝단 delta**(위치 3 + 회전 3 + 그리퍼 1)이므로, 순서를 뒤집고 부호를 바꾸면 되돌아갑니다
- 되돌리는 범위를 **"그리퍼 닫은 시점보다 10스텝 앞"** 까지로 제한하고(`--rollback-pre`), 전체 길이도 60스텝으로 묶습니다(`--rollback-max`) → **초기 자세까지 갈 수 없습니다**
- 끝나는 자리는 "물체를 집기 직전"이고, 그 상태는 **원래 학습 분포 안에** 있습니다 ([ReSteer](../../02_논문노트/ReSteer.md) 가 말하는 "분포가 겹치는 상태")
- 기록: `home_dist_before_cm` / `home_dist_after_cm` — 초기 위치와의 거리를 전환 전후로 남겨서 **정말 초기 자세로 안 갔는지** 확인합니다

- **안전장치**: 그리퍼가 닫혀 있지 않으면 되돌리지 않습니다. 재개(A2) 단계에서도 전략이 적용되는데, 빈손일 때 되돌리면 **그리퍼를 닫은 채 B 궤적을 되짚어 B 를 망치기** 때문입니다 (2026-09-18 에 발견해 수정)

**최종 목표는 스크립트를 없애는 것입니다.** 어떤 전략이 통하면 그 궤적을 LoRA 로 증류해, 추론할 때는 정책이 스스로 하도록 만듭니다.

> ❌ **2026-09-18 결과: rollback 은 실패했습니다** (19% vs flush 32%, p=0.064).
> 역재생 자체는 정확했지만(오차 2.4cm) **되돌아간 거리가 7.7cm 뿐**이라 초기 위치에서 여전히 21cm 떨어져 있었습니다.
> → [회복 실험](recovery/README.md)

### `rtc` 는 어떻게 동작하나

```
지시 A 로 움직이는 중:   [a1 a2 a3 ... a10 | a11 ... a50]   ← 앞 10개 실행, 뒤 40개 남음
                                            ↓ 지시가 B 로 바뀜
새 동작 생성 (지시 B):   노이즈 → (10단계 다듬기, 매 단계마다 "남은 a11~a20 쪽으로 끌어당김") → [b1 ... b50]
```

- 앞부분은 **이전 동작과 이어지게**, 뒷부분은 **새 지시대로** → 방향은 바뀌되 동작은 끊기지 않음
- 전환 이후에만 적용 (전환 전 궤적은 다른 전략과 똑같이 해서 공정하게 비교)
- 옵션: `--rtc-horizon 10`(따라갈 길이), `--rtc-delay 0`(완전 고정 길이), `--rtc-guidance 10`(끌어당김 최대 세기)

### `bon` 은 어떻게 동작하나

```
1. 성공 궤적 지도 만들기 (build_success_manifold.py)
   태스크별로 "성공한 에피소드에서 팔 끝이 지나간 위치" 최대 6000개

2. 전환 이후 매 추론마다
   후보 N개 뽑기 (노이즈만 다르게, 기본 8개)
       ↓
   후보마다 앞으로 20스텝 동안 팔 끝이 갈 위치를 대략 계산
       ↓
   그 위치들이 "새 태스크 성공 궤적"에서 얼마나 먼지 평균
       ↓
   가장 가까운 후보 실행
```

- **초기 자세로 가는 게 아니라, 성공 궤적이 지나가는 길목으로 합류**하게 유도 → 제약을 지킴
- Q-Planning 은 1B 파라미터 심판을 학습하지만, 우리는 1080 Ti 에 맞게 **학습 없는 거리 점수**로 대체
- 옵션: `--bon-n 8`, `--bon-horizon 20`, `--bon-gain 0.6`(동작 → 실제 이동 근사 배율)

## 2. 데이터 수집 모드 (`collect_robust_data.py --mode`)

대부분의 모드는 **정책이 스스로 움직인 궤적**만 저장하고, 스크립트로 자세를 만든 구간은 저장하지 않습니다.
초기 자세 복귀(retreat) 같은 **제약을 깨는 동작을 배우면 안 되기** 때문입니다.

**단 `rollback`·`strategy` 모드는 예외입니다.** 제약을 지키는 동작이라면 그 구간을 **일부러 저장해서
정책이 스스로 하게 만듭니다**(증류). 이게 "추론할 때 스크립트를 없애는" 방법입니다.

구현은 `Episode.step()` 의 **기록 훅**(`ep.record`)으로 합니다. 전략이 만드는 모든 스텝이 자동으로 잡히므로
전략마다 따로 코드를 쓸 필요가 없습니다.

```bash
# ret_part(f=0.5) 로 전환하면서 스크립트 구간까지 수집 → LoRA 학습 → 스크립트 없이 평가
./run_distill.sh ret_part 0.5 v3
```

⛔ `retreat`(초기 자세 완전 복귀)은 **증류 대상이 될 수 없습니다.** 제약 위반 동작을 정책에 심는 것이기 때문입니다.

| 모드 | 무엇을 모으나 | 저장 조건 | 참고 논문 | 사용 |
|---|---|---|---|---|
| `pose` | 시작 자세를 틀어놓고 수행 | 성공 | [DART](../../02_논문노트/DART.md), [Reverse Curriculum](../../02_논문노트/Reverse-Curriculum.md) | LoRA 1차(≤8cm), 2차(8~20cm) |
| `switch` | 물체를 쥔 채 **그 자리에서** B 로 전환 | B 성공 | [SwitchVLA](../../02_논문노트/SwitchVLA.md) 의 전환 설정 | LoRA 1차 |
| `hindsight` | switch 와 같음 | B 성공 **또는 우연히 다른 태스크 달성** | [HER](../../02_논문노트/HER.md) | LoRA 2차 |
| `chain` | 태스크를 **리셋 없이 연달아** | 두 번째 태스크부터 성공 구간 | (재개 문제용으로 설계) | 준비됨 |
| `noise` | 수행 중 **동작을 일부러 밀어** 벗어나게 | 성공 (정답은 노이즈 없는 동작) | [DART](../../02_논문노트/DART.md) | 준비됨 |
| **`rollback`** | 전환 순간 **최근 동작을 거꾸로 재생**해 물체를 집었던 자리에 놓고 B 로 감 | B 성공. **되돌리는 구간(R)까지 저장** | [SwitchVLA](../../02_논문노트/SwitchVLA.md) 의 rollback | ❌ 전략 자체가 실패 |
| **`strategy`** | **어떤 전환 전략이든** 적용하고 그 **스크립트 구간까지 저장** (`--collect-strategy`) | B 성공 | 증류(distillation) | 준비됨 — 용량-반응 결과를 보고 대상 전략 결정 |


### `noise` 는 어떻게 동작하나

```
매 스텝:
  정책이 낸 깨끗한 동작 c  →  저장할 정답
  가끔(에피소드당 최대 2번, 6스텝씩) 같은 방향 노이즈를 더해 실행 → 팔이 궤도에서 밀려남
  → 다음 스텝부터 정책이 스스로 돌아오는 동작을 냄 → 그것도 정답으로 저장
성공한 에피소드만 남김
```

"밀려났다가 돌아오는 법"을 배우는 데이터입니다. 시험 결과 3번 모두 성공, 에피소드당 7~12스텝이 밀렸습니다. 처음엔 노이즈가 너무 세서(300스텝 중 150스텝) 전부 실패했고, DART 의 "노이즈는 실제 오차 수준에 맞춘다"에 따라 줄였습니다.

## 2-2. 노이즈 조종 (2026-09-18 추가)

| 옵션 | 무엇을 하나 | 결과 |
|---|---|---|
| `--switch-noise-seed S` | 전환 순간부터 노이즈 **순서를 고정** | 같은 쌍에서 +30%p, **처음 보는 쌍에서 −60%p** ❌ |
| `--switch-noise-reseed` | 매 추론마다 같은 노이즈 (완전 결정적) | **0%** ❌ — 즉시 맴돌기 |
| `--switch-noise-first-only` | 첫 chunk 만 고정 | 기준선과 동일 (효과 없음) |
| `--noise-seed-from-start` | 전환 없이 처음부터 고정 | 태스크마다 100→60% / 70→100% |
| **`--noise-shift μ.npy`** | 노이즈 **분포의 중심만 이동** (z = μ + ε) | ⏳ CEM 으로 최적화 중 |

**왜 "중심 이동"인가**: 노이즈를 고정하면 0% 가 되므로(변화가 진행에 필수), 고정하지 않고
분포 중심만 옮겨야 합니다. μ = 0 이면 원래 정책과 완전히 같습니다.

```bash
# CEM 으로 μ 찾기 (쌍당 약 2시간) → 미사용 에피소드에서 검증
python cem_noise.py --task-a 8 --task-b 7 --iters 8 --candidates 6 --episodes 6 --out outputs/cem_8_7
python switch_experiment.py --task-a 8 --task-b 7 --switch-at grasp:3 --strategy flush \
  --noise-shift outputs/cem_8_7/mu_best.npy --episodes 10 --start-episode 10
```

