# LIBERO + SmolVLA 직접 돌려보기 (연구실 PC 기준, 2026-09-16 검증)

## 📌 쉬운 말 요약

명령어 몇 줄로 **가상 로봇이 "그릇을 접시에 놓아" 같은 지시를 수행하는 것**을 볼 수 있습니다. 설치는 아래 순서대로 하면 10~20분이면 끝납니다(인터넷 속도에 따라 다름). GPU는 1080 Ti로 충분합니다.

> LAB05 문서는 conda + Python 3.12 + LeRobot main 기준인데, **그 조합은 지금 안 됩니다**(main이 Python 3.12를 요구하고, 그 위에서 LIBERO 의존성이 꼬입니다). 아래는 실제로 돌아간 조합입니다.

## 2. 가상환경 만들기

```bash
mkdir -p ~/smolVLA && cd ~/smolVLA && uv venv .venv --python 3.10
```

**Python 3.10** 입니다. LeRobot 0.4.4가 3.10에서 동작하고, 최신 main(3.12 요구)은 LIBERO와 같이 쓰기 어렵습니다.

## 3. 설치

먼저 override 파일을 만듭니다. LIBERO 실행에 필요 없는데 빌드에서 문제를 일으키는 패키지 두 개를 빼는 설정입니다.

```bash
cd ~/smolVLA && printf "evdev; sys_platform == 'never'\negl-probe; sys_platform == 'never'\nhf-egl-probe; sys_platform == 'never'\n" > .overrides.txt
```

설치합니다. 약 5~10분 걸립니다.

```bash
cd ~/smolVLA && uv pip install --python .venv/bin/python "lerobot[libero,smolvla]==0.4.4" --overrides .overrides.txt --torch-backend cu126
```

`--torch-backend cu126` 이 중요합니다. 1080 Ti(Pascal)는 cu128 빌드에서 동작하지 않습니다.

확인 (기대: `2.10.0+cu126 True (6, 1)`):

```bash
cd ~/smolVLA && .venv/bin/python -c "import torch; print(torch.__version__, torch.cuda.is_available(), torch.cuda.get_device_capability())"
```

## 6. ⭐ 지시를 도중에 바꿔보기 (전환 실험)

우리가 만든 스크립트입니다. 코드는 [switch_experiment](switch_experiment/) 에 있습니다.

```bash
cd ~/smolVLA && .venv/bin/python switch_experiment.py --task-a 8 --task-b 7 --switch-at grasp:3 --strategy retreat --episodes 3 --video --out outputs/my_test
```

- `--switch-at grasp:3` : 물체를 잡고 3스텝 뒤에 지시 교체 (`step:15` 처럼 고정 스텝도 가능)
- `--strategy` : `flush`(즉시 교체) / `keep`(남은 chunk 다 쓰고) / `blend`(섞기) / **`rollback`(최근 동작을 거꾸로 재생해 집었던 자리에 내려놓기)** / `retreat`(내려놓고 초기 자세 복귀 — **진단용**) / `none`(안 바꿈)
- 영상은 `outputs/my_test/videos/` 에 생깁니다
- 저사양 조건을 재현하려면 `--latency-steps 11` (1080 Ti 실측 0.56초)

같은 조건을 `flush`로도 돌려서 영상을 비교해보면 차이가 바로 보입니다.

```bash
cd ~/smolVLA && .venv/bin/python switch_experiment.py --task-a 8 --task-b 7 --switch-at grasp:3 --strategy flush --episodes 3 --video --out outputs/my_test
```

## 7. 결과 보기

에피소드마다 JSON 한 줄이 출력됩니다. 중요한 항목은 이렇습니다.

| 항목 | 뜻 |
|---|---|
| `grasp_step` | 물체를 잡은 스텝 |
| `holding_at_switch` | 전환 순간에 물체를 쥐고 있었는지 |
| `b_success` / `a_resume_success` | B 성공 / B 이후 A 재개 성공 |
| `b_failure_type` | 실패 유형 (물체 낙하 / 지시 무시 / 얼어붙음 / 시간 초과) |
| `jerk` | 동작이 튀는 정도 (작을수록 부드러움) |
| `home_dist_after_cm` | 전환 처리 뒤 끝단이 **초기 위치에서 얼마나 떨어져 있는지** (커야 제약을 지킨 것) |
| `to_b_rollback_steps` | rollback 이 되돌리는 데 쓴 스텝 수 |

표와 그래프로 정리:

```bash
cd ~/smolVLA && .venv/bin/python analyze.py
```

## 8. ⭐ 노이즈 바꿔 보기 (2026-09-18 발견)

같은 상태·같은 지시인데 **생성 노이즈만 바꾸면** 성공률이 크게 달라집니다.
직접 확인해 보세요 — 같은 에피소드(`--start-episode 10`)에서 시드만 바꾸면 됩니다.

```bash
# 기본 (매번 새 노이즈)
cd ~/smolVLA && .venv/bin/python switch_experiment.py --task-a 8 --task-b 7 --switch-at grasp:3 \
  --strategy flush --episodes 10 --start-episode 10 --out outputs/my_noise

# 노이즈 순서를 고정 (이 쌍에서 좋았던 시드)
cd ~/smolVLA && .venv/bin/python switch_experiment.py --task-a 8 --task-b 7 --switch-at grasp:3 \
  --strategy flush --switch-noise-seed 10679 --episodes 10 --start-episode 10 --out outputs/my_noise

# 매 추론마다 같은 노이즈 (완전히 결정적) → 0% 가 나옵니다
cd ~/smolVLA && .venv/bin/python switch_experiment.py --task-a 8 --task-b 7 --switch-at grasp:3 \
  --strategy flush --switch-noise-seed 10679 --switch-noise-reseed --episodes 10 --start-episode 10 \
  --out outputs/my_noise
```

⚠️ **시드 10679 는 8→7 에서만 좋습니다.** 다른 쌍(6→0)에서는 80% → 20% 로 오히려 해롭습니다.
좋은 노이즈는 장면마다 다릅니다 → [노이즈 시드 보고서](noise_seed/README.md)

```bash
# 초기 자세 쪽으로 75% 만 되돌리고 전환 (67% — 단 자연스러움은 리셋에 가깝습니다)
cd ~/smolVLA && .venv/bin/python switch_experiment.py --task-a 8 --task-b 7 --switch-at grasp:3 \
  --strategy ret_part --retreat-frac 0.75 --episodes 10 --out outputs/my_retpart
```

## 9. 진단 도구 (2026-09-18 추가)

```bash
# 같은 전환 상태에서 노이즈만 바꿔 8번 다시 굴리기 — 후보 선택의 상한
cd ~/smolVLA && .venv/bin/python oracle_bon.py --pairs 8:7 --episodes 3 --n 8 --out outputs/my_oracle
cd ~/smolVLA && .venv/bin/python analyze_oracle.py

# 조종 가능성(CMI) — "이 상태에서 지시를 바꾸면 동작이 실제로 바뀌는가"
cd ~/smolVLA && .venv/bin/python steerability.py --tasks 8 --episodes 2 --k 8 --out outputs/my_steer
cd ~/smolVLA && .venv/bin/python analyze_steer.py

# 1회 추론 시간 실측 (저사양 조건을 정하는 근거)
cd ~/smolVLA && .venv/bin/python bench_inference.py "내 GPU"
```

`oracle_bon.py` 는 시뮬레이터 상태를 저장(`get_sim_state`)하고 되돌려(`regenerate_obs_from_state`) 같은 지점에서 다시 시작합니다. 상태를 되돌릴 때 **스텝 카운터도 같이 되돌려야** 합니다 (`inner.timestep = 0`), 아니면 `executing action in terminated episode` 오류가 납니다.

## 8. 자주 나는 오류

| 증상 | 해결 |
|---|---|
| `mujoco` 렌더링 오류 | 명령 앞에 `MUJOCO_GL=egl` 를 붙였는지 확인 |
| `no kernel image is available` | torch를 cu126 빌드로 다시 설치 (`--torch-backend cu126`) |
| 설치 중 `evdev` / `egl-probe` 빌드 실패 | 3번의 `.overrides.txt` 를 빼먹지 않았는지 확인 |
| 느림 | 정상입니다. 1080 Ti에서 에피소드당 10~50초. `--n-action-steps 10` 이면 빨라집니다(기본 1) |
| GPU 메모리 부족 | 다른 실험이 돌고 있는지 `nvidia-smi` 확인. 1회 추론에 약 2.2GB |
