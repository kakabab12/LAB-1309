# LAB 06. PiPER 실물 로봇

## 📌 쉬운 말 요약

**뭐 하는 실습?** 연구실의 진짜 로봇 팔(PiPER)을 다룹니다.

**⚠️ 먼저 알 것: 안전**
진짜 로봇은 사람을 다치게 할 수 있습니다. 순서를 꼭 지키세요.
1. **비상 정지 버튼이 어디 있는지 먼저 확인**
2. 처음엔 **속도를 가장 느리게**
3. 새 프로그램을 처음 돌릴 때는 **손을 비상 정지에 올려두기**
4. 로봇 주변에 사람이나 물건 두지 않기

**처음에는 움직이지 말고 "읽기만" 하세요.**
손으로 팔을 움직여보면서 **관절 숫자가 어떻게 변하는지** 보는 것부터 시작합니다. 그리퍼(집게)를 열고 닫으며 숫자 범위를 기록해두세요. 이게 나중에 "물건을 잡고 있나?"를 판단하는 기준이 됩니다.

**좋은 소식**: 위고로보틱스가 만든 프로그램이 있어서 **로봇을 손으로 움직이면 자동으로 데이터가 저장**됩니다. 처음부터 만들 필요 없어요.

---

> 목표: 실제 로봇을 안전하게 다루고, 데이터를 모으고, 정책을 실행하기
> 소요: 2~4주
> ⚠️ **안전이 최우선입니다.**

## 0. 안전 수칙 (먼저 읽기)

| 규칙 | 이유 |
|---|---|
| **비상 정지 버튼 위치를 먼저 확인** | 이상 동작 시 즉시 정지 |
| 로봇 작업 반경 안에 사람·물건 두지 않기 | 충돌 위험 |
| **처음에는 속도를 최저로** | 학습된 정책은 예측 불가한 동작을 할 수 있음 |
| 새 정책을 처음 돌릴 때는 **손을 비상 정지에 올려두기** | |
| 관절 한계·작업 공간 제한을 소프트웨어로 걸기 | 무리한 자세 방지 |
| 혼자 작업하지 않기 (가능하면) | |
| 전원을 끌 때는 팔을 안전한 자세로 | 급격히 떨어질 수 있음 |

## 1. 하드웨어 연결

```
[Ubuntu PC] --USB--> [CAN-USB 어댑터] --CAN--> [PiPER]
     |
     +--USB--> [카메라 1: 정면]
     +--USB--> [카메라 2: 손목]
```

**체크리스트**
- [ ] CAN-USB 어댑터 (gs_usb 호환)
- [ ] 전원 어댑터
- [ ] 리더 팔 (원격조종용, 있으면)
- [ ] USB 카메라 2대 + 거치대

## 2. CAN 통신 설정

```bash
sudo apt install can-utils iproute2 ethtool
```

인터페이스 확인

```bash
ip link show | grep can
```

활성화 (비트레이트는 PiPER 문서 확인, 보통 1Mbps)

```bash
sudo ip link set can0 up type can bitrate 1000000
```

통신 확인 (로봇이 켜져 있으면 메시지가 흘러나옵니다)

```bash
candump can0
```

**안 되면 확인할 것**
- 어댑터가 인식되는가: `dmesg | tail`
- 권한 문제: `sudo` 필요 여부
- 비트레이트가 맞는가

## 3. piper_sdk 기본

```bash
pip install piper_sdk
```

`piper_hello.py` (실제 API 이름은 설치한 SDK 문서를 확인하세요)

```python
from piper_sdk import C_PiperInterface

piper = C_PiperInterface("can0")
piper.ConnectPort()
piper.EnableArm()                    # 모터 활성화

# 현재 상태 읽기
joint = piper.GetArmJointMsgs()
pose  = piper.GetArmEndPoseMsgs()
print("관절:", joint)
print("끝단:", pose)
```

**먼저 해볼 것 (움직이기 전에)**
1. **읽기만** 하면서 손으로 팔을 움직여보기 → 관절값이 어떻게 변하는지
2. 각 관절의 **최소/최대 값** 기록
3. 그리퍼를 손으로 열고 닫으며 **값의 범위** 기록 ← LAB 04의 판정 함수에 필요
4. 끝단 좌표계의 **원점과 축 방향** 파악

## 5. 카메라 세팅

`camera_check.py`

```python
import cv2

for i in range(10):
    cap = cv2.VideoCapture(i)
    if cap.isOpened():
        ok, frame = cap.read()
        if ok:
            print(f"카메라 {i}: {frame.shape}")
            cv2.imwrite(f"cam{i}.jpg", frame)
        cap.release()
```

**설정 (중요)**

```python
cap = cv2.VideoCapture(0)
cap.set(cv2.CAP_PROP_FRAME_WIDTH, 640)
cap.set(cv2.CAP_PROP_FRAME_HEIGHT, 480)
cap.set(cv2.CAP_PROP_AUTOFOCUS, 0)        # 자동 초점 끄기
cap.set(cv2.CAP_PROP_AUTO_EXPOSURE, 0.25) # 자동 노출 끄기 (값은 카메라마다 다름)
```

⚠️ 이전 키오스크 프로젝트에서 확인했듯 **카메라마다 설정이 안 먹히는 경우가 있습니다.** `set()`이 True를 반환해도 실제로 안 바뀔 수 있으니 **찍힌 이미지로 확인**하세요.

**고정**: 정면 카메라 스탠드 위치를 **테이프로 표시**. 데이터 수집 때와 실행 때 같아야 합니다.

## 7. 데이터 수집

### 태스크 설계 (전환 연구용)

**핵심 원칙: 같은 장면에 물체를 여러 개 두고, 지시로만 구분되게**

| 태스크 | 지시 문장 |
|---|---|
| A | "빨간 블록을 컵에 넣어" |
| B | "파란 블록을 접시에 올려" |
| C | "노란 블록을 상자에 넣어" |

⭐ 이렇게 해야 모델이 **언어를 보지 않으면 풀 수 없습니다.** (LIBERO-Goal과 같은 원리)

### 수집 계획

| 종류 | 개수 | 비고 |
|---|---|---|
| 태스크당 일반 데모 | 50개 | 물체 위치를 조금씩 바꿔가며 |
| **전환 데모** | 30~50개 | A를 하다 B로 넘어가는 시연 |

### 수집할 때 주의

- 시연 속도를 **일정하게**
- 실패한 시연은 **지우기** (모델이 실패를 배웁니다)
- 물체 위치를 매번 **조금씩 바꾸기** (일반화)
- 조명이 바뀌지 않게
- 중간중간 **데이터를 열어보며 확인**

## 9. 정책 실행 (가장 조심할 단계)

## 10. 실물 전환 실험
