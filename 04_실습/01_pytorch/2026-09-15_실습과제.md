## 과제 1. 선형회귀 — 학습으로 2와 3 찾기

```python
import torch
import torch.nn as nn
import torch.optim as optim

torch.manual_seed(42)
x_train = torch.randn(100, 1)
y_train = 2 * x_train + 3 + torch.randn(100, 1) * 0.01   # 노이즈 추가

model = nn.Linear(1, 1)
criterion = nn.MSELoss()
optimizer = optim.SGD(model.parameters(), lr=0.01)

for epoch in range(1, 1001):
    outputs = model(x_train)
    loss = criterion(outputs, y_train)
    optimizer.zero_grad()
    loss.backward()
    optimizer.step()
    if epoch % 200 == 0:
        w, b = model.weight.item(), model.bias.item()
        print(f"Epoch {epoch:4d}/1000 | Loss: {loss.item():.6f} | W: {w:.4f}, b: {b:.4f}")
```

결과

```
Epoch  200/1000 | Loss: 0.001704 | W: 1.9786, b: 2.9683
Epoch  400/1000 | Loss: 0.000078 | W: 1.9998, b: 2.9999
Epoch 1000/1000 | Loss: 0.000078 | W: 2.0001, b: 3.0004
```

**읽는 법**: 400 에포크 이후 loss가 0.000078에서 더 안 내려갑니다. 이건 학습이 덜 된 게 아니라 **노이즈의 크기**입니다. 데이터에 표준편차 0.01짜리 노이즈를 넣었으니 분산은 0.01² = 0.0001이고, MSE가 그 근처에서 멈추는 게 정상입니다. 이 값을 **노이즈 바닥(noise floor)** 이라고 부릅니다.

## 과제 3. CPU vs GPU 시간 비교 — T4에서 21배

```
CPU 실행 시간: 13.4970 초     # 2000×2000 행렬곱 100회
GPU 실행 시간: 0.6416 초
속도 향상: 21.04배
```

`torch.cuda.Event` 와 `torch.cuda.synchronize()` 를 쓴 게 정확합니다. GPU는 명령을 비동기로 처리해서 `time.time()` 으로 재면 실제보다 짧게 나옵니다.

**같이 볼 것**: 과제 2의 MNIST는 GPU(353초)가 CPU(386초)보다 거의 안 빨랐습니다. 행렬곱은 21배인데 왜 그럴까요?

| | 행렬곱 | MNIST MLP |
|---|---|---|
| 한 번에 하는 계산량 | 매우 큼 (2000³) | 아주 작음 (784×128) |
| 병목 | **계산** | **데이터 공급**(DataLoader)과 커널 호출 overhead |

**GPU는 계산이 병목일 때만 빨라집니다.** 모델이 작으면 GPU가 놀고, 데이터를 나르는 시간이 대부분입니다. `DataLoader(num_workers=2, pin_memory=True)` 로 개선할 수 있습니다. VLA처럼 큰 모델에서는 계산이 병목이라 GPU 효과가 그대로 납니다.

## 과제 4. 배치 크기별 VRAM — 수치가 잘못 나옴 ⚠️

T4에서 실행한 결과

```
Batch Size:  8 | Allocated VRAM: 12681.26 MB | Reserved VRAM: 12754.00 MB
Batch Size: 16 | Allocated VRAM: 12682.52 MB | Reserved VRAM: 12818.00 MB
```

배치를 2배로 늘렸는데 메모리가 **1.26MB밖에** 안 늘었습니다. 이상합니다. 모델은 conv 3→16→32에 입력 128×128이라 배치 8이면 활성값이 수십 MB 수준이어야 하는데 12.6GB가 잡혀 있습니다.

**원인**: Colab은 셀을 다시 실행해도 **변수가 그대로 남습니다.** 앞서 돌린 큰 버전(512×512 입력, 채널 64/128, 배치 64)의 `dummy_input`, `output`, `loss` 가 아직 전역 변수로 살아 있어서 그 메모리(약 12.6GB)가 해제되지 않았습니다. 그 위에 작은 텐서가 얹히니 증가분이 안 보이는 것입니다.

**고친 코드**

```python
import torch, torch.nn as nn, gc

device = 'cuda'
model = nn.Sequential(
    nn.Conv2d(3, 16, 3, padding=1), nn.ReLU(),
    nn.Conv2d(16, 32, 3, padding=1), nn.ReLU(),
    nn.AdaptiveAvgPool2d((1, 1)), nn.Flatten(), nn.Linear(32, 10)
).to(device)

for b in [8, 16, 32, 64]:
    # 1) 이전 반복의 텐서를 확실히 지운다
    for name in ["dummy_input", "output", "loss"]:
        if name in globals():
            del globals()[name]
    model.zero_grad(set_to_none=True)      # 기울기도 메모리를 차지함
    gc.collect(); torch.cuda.empty_cache()

    # 2) 최고 사용량 기록을 초기화하고 측정
    torch.cuda.reset_peak_memory_stats(device)
    dummy_input = torch.randn(b, 3, 128, 128, device=device)
    output = model(dummy_input)
    loss = output.sum()
    loss.backward()
    peak = torch.cuda.max_memory_allocated(device) / 1024**2
    print(f"Batch {b:3d} | 최고 사용량: {peak:8.2f} MB")
```

**바뀐 점 세 가지**

1. 이전 변수를 `del` 로 지우고 `gc.collect()` — 변수가 살아 있으면 메모리가 안 풀립니다
2. `model.zero_grad(set_to_none=True)` — 파라미터 기울기도 메모리입니다
3. `memory_allocated()`(지금 이 순간) 대신 **`max_memory_allocated()`(구간 최고값)** — 순전파 중간의 최대치를 봐야 배치 영향이 보입니다

**기대 결과**: 배치가 2배면 활성값도 대략 2배로 늘어야 합니다. 그 비례 관계를 확인하는 게 이 과제의 목적입니다.

**참고**: `Allocated` 는 텐서가 실제로 쓰는 양, `Reserved` 는 PyTorch가 OS에서 미리 받아둔 양입니다. Reserved가 더 큰 건 정상이고, `nvidia-smi` 에는 Reserved가 보입니다.
