## 과제 1. 선형회귀 — 학습으로 2와 3 찾기

```python
import torch
import torch.nn as nn
import torch.optim as optim

torch.manual_seed(42)
x_train = torch.randn(100, 1)
y_train = 2 * x_train + 3 + torch.randn(100, 1) * 0.01   # 노이즈 추가

model = nn.Linear(1, 1)
criterion = nn.MSELoss()
optimizer = optim.SGD(model.parameters(), lr=0.01)

for epoch in range(1, 1001):
    outputs = model(x_train)
    loss = criterion(outputs, y_train)
    optimizer.zero_grad()
    loss.backward()
    optimizer.step()
    if epoch % 200 == 0:
        w, b = model.weight.item(), model.bias.item()
        print(f"Epoch {epoch:4d}/1000 | Loss: {loss.item():.6f} | W: {w:.4f}, b: {b:.4f}")
```

결과

```
Epoch  200/1000 | Loss: 0.001704 | W: 1.9786, b: 2.9683
Epoch  400/1000 | Loss: 0.000078 | W: 1.9998, b: 2.9999
Epoch 1000/1000 | Loss: 0.000078 | W: 2.0001, b: 3.0004
```

**읽는 법**: 400 에포크 이후 loss가 0.000078에서 더 안 내려갑니다. 이건 학습이 덜 된 게 아니라 **노이즈의 크기**입니다. 데이터에 표준편차 0.01짜리 노이즈를 넣었으니 분산은 0.01² = 0.0001이고, MSE가 그 근처에서 멈추는 게 정상입니다. 이 값을 **노이즈 바닥(noise floor)** 이라고 부릅니다.

과제 3의 코드는 `torch.cuda.Event` 로 시간을 재고 있어 맞게 작성돼 있습니다. GPU는 명령을 비동기로 처리해서 `time.time()` 으로 재면 실제보다 짧게 나오는데, 그걸 피한 방식입니다. `torch.cuda.synchronize()` 를 넣은 것도 같은 이유입니다.

연구실 PC(1080 Ti)에서 바로 돌려볼 수도 있습니다.

```bash
cd ~/smolVLA && .venv/bin/python -c "
import torch, time
X = torch.randn(2000, 2000); W = torch.randn(2000, 2000)
t = time.time()
for _ in range(100): torch.matmul(X, W)
print('CPU', round(time.time() - t, 2), '초')
Xg, Wg = X.cuda(), W.cuda(); torch.matmul(Xg, Wg); torch.cuda.synchronize()
s, e = torch.cuda.Event(True), torch.cuda.Event(True)
s.record()
for _ in range(100): torch.matmul(Xg, Wg)
e.record(); torch.cuda.synchronize()
print('GPU', round(s.elapsed_time(e) / 1000, 3), '초')"
```
