# 1단계. 딥러닝 기초 (3~4주)

## 📌 쉬운 말 요약

**이 문서는 뭐 하는 곳?** AI 모델의 작동 원리와 용어를 배웁니다.

**핵심은 딱 하나**: 모델 = 숫자 수억 개가 든 계산식. 학습 = 그 숫자를 조금씩 고쳐서 답을 맞히게 만드는 것.

**여기서 꼭 가져갈 3가지**
1. **shape(모양)** — 데이터가 (배치, 채널, 높이, 너비) 같은 형태로 다녀요. 여기가 안 맞아서 나는 오류가 제일 많습니다.
2. **정규화** — 관절 각도는 -3~3, 그리퍼는 0~1처럼 숫자 범위가 제각각이라 맞춰줘야 해요. **안 맞추면 로봇이 엉뚱하게 움직입니다.**
3. **Flow Matching** — 요즘 로봇 모델이 동작을 만드는 방식. "지저분한 낙서에서 시작해 점점 깔끔한 그림으로 다듬는다"고 생각하면 됩니다.

**어려우면 건너뛰어도 되는 것**: 수식, LoRA 같은 학습 기법 이름. 나중에 필요할 때 돌아오세요.

---

> VLA 논문을 읽으려면 여기 나오는 용어가 **전부** 나옵니다. 대충 넘기면 4단계에서 막힙니다.

## 1-1. PyTorch 기본

### 배울 것

| 주제 | 핵심 | 왜 필요한가 |
|---|---|---|
| **Tensor** | 모양(shape), dtype, device(cpu/cuda) | 모든 데이터가 텐서 |
| **autograd** | `requires_grad`, `backward()`, `no_grad()` | 학습의 원리 |
| **nn.Module** | `__init__`에 층 정의, `forward`에 계산 | 모든 모델의 뼈대 |
| **손실 함수** | MSE, CrossEntropy, **L1** | 로봇 동작 예측은 주로 L1/MSE |
| **optimizer** | SGD, **AdamW**, learning rate | 실제로 학습시키는 부분 |
| **scheduler** | cosine, warmup | VLA 학습에 거의 항상 나옴 |
| **Dataset / DataLoader** | `__len__`, `__getitem__`, batch, num_workers | 로봇 데이터도 이 형태 |
| **저장/불러오기** | `state_dict`, checkpoint | 실험 관리 |

### 꼭 이해할 개념

**shape을 항상 의식하기** — 딥러닝 디버깅의 90%는 shape 문제입니다.

```
이미지 배치:  (B, C, H, W) = (8, 3, 256, 256)
                B=배치, C=채널(RGB), H=높이, W=너비
동작 chunk:   (B, T, D)    = (8, 50, 7)
                T=시간 스텝, D=동작 차원(6축+그리퍼)
```

**정규화(normalization)** — ⭐ 로봇 데이터에서 가장 많이 실수하는 부분

- 관절 각도는 -3.14 ~ 3.14, 그리퍼는 0 ~ 1처럼 **범위가 제각각**
- 그대로 학습시키면 범위가 큰 값만 배우게 됨
- 그래서 **데이터셋 통계(평균, 표준편차 또는 min/max)로 정규화**
- ⚠️ **학습할 때와 실행할 때 같은 통계를 써야 함**. 다르면 로봇이 엉뚱하게 움직임

**mixed precision (fp32 / fp16 / bf16)**

| 형식 | 메모리 | 안정성 | 1080 Ti |
|---|---|---|---|
| fp32 | 많이 씀 | 안정적 | ✅ |
| fp16 | 절반 | 값이 넘칠 수 있음 | △ (가속 없음) |
| **bf16** | 절반 | 안정적 | ❌ 미지원 |

→ 1080 Ti에서는 **fp32**로 돌게 되고, 그만큼 메모리를 더 쓰고 느립니다.

### 실습 과제

1. **선형회귀를 직접** — `y = 2x + 3` 데이터를 만들고 학습으로 2와 3을 찾기
2. **MNIST 분류기** — Dataset/DataLoader/학습루프를 **복붙 없이** 작성
3. 같은 모델을 CPU와 GPU에서 돌려 **시간 차이 측정**
4. 배치 크기를 8 → 64로 올리며 `nvidia-smi`로 **VRAM 변화 관찰**

## 1-3. ⭐ Transformer

**VLA의 심장입니다. 여기는 확실히 이해하세요.**

| 개념 | 이해해야 할 것 |
|---|---|
| **토큰(token)** | 문장을 조각낸 단위. 이미지 패치도 토큰이 됨 |
| **임베딩** | 토큰을 벡터로 바꾸기 |
| **self-attention** | Q(질문), K(열쇠), V(내용). "어떤 토큰이 어떤 토큰을 봐야 하나" |
| **cross-attention** | 다른 종류의 정보를 참조 (예: 동작이 이미지를 참조) |
| **multi-head** | 여러 관점으로 동시에 보기 |
| **positional encoding** | 순서 정보 넣기 |
| **causal mask** | 미래를 못 보게 가리기 (자기회귀 생성) |
| **자기회귀 vs 병렬 출력** | ⭐ 한 토큰씩 vs 한 번에. **속도 차이의 핵심** |

## 1-4. 시각-언어 모델 (VLM)

| 주제 | 핵심 |
|---|---|
| **CLIP / SigLIP** | 이미지와 텍스트를 **같은 벡터 공간**에 놓기 |
| **VLM 구조** | 이미지 인코더 + 언어 모델을 연결 |
| **대표 모델** | PaliGemma(π0의 백본), SmolVLM(SmolVLA의 백본), Florence-2 |
| **토크나이저** | 문장을 토큰 번호로 바꾸는 것 |

> **VLA = VLM + 동작 출력.** 그래서 VLM을 알면 VLA 구조가 바로 보입니다.

## 1-5. ⭐ Diffusion과 Flow Matching

**SmolVLA와 π0가 이 방식으로 동작을 만듭니다.**

| 개념 | 쉬운 설명 |
|---|---|
| **Diffusion** | 정답에 노이즈를 점점 섞어 망가뜨리는 과정을 배우고, **거꾸로 복원**하면서 새 결과를 만듦 |
| **denoising step** | 복원 단계 수. 많으면 품질↑ 속도↓ |
| **Flow Matching** | 노이즈에서 정답까지 **직선에 가까운 경로**를 배우는 방식. diffusion보다 **적은 단계로 빠르게** |
| **왜 로봇에 쓰나** | 같은 상황에서도 정답 동작이 여러 개일 수 있는데(다중 모드), 평균을 내면 이상한 동작이 됨. diffusion/flow는 그걸 잘 다룸 |

**실험 변수로도 중요**: 복원 단계 수(`num_steps`)를 줄이면 **추론이 빨라지지만 품질이 떨어질 수 있음** → 저사양 연구와 직결됩니다.

## 1-6. 학습 기법 용어

| 용어 | 뜻 |
|---|---|
| **파인튜닝** | 사전학습된 모델을 내 데이터로 조금 더 학습 |
| **LoRA** | 원래 가중치는 얼리고 작은 행렬만 학습 → **메모리 절약** |
| **동결(freeze)** | 일부 층을 학습에서 제외 |
| **gradient accumulation** | 배치를 나눠 여러 번 계산 후 한 번에 갱신 → **작은 GPU에서 큰 배치 효과** |
| **gradient checkpointing** | 중간 결과를 버리고 다시 계산 → 메모리↓ 속도↓ |
| **EMA** | 가중치의 이동평균을 따로 유지 |
| **과적합(overfitting)** | 학습 데이터만 잘하고 새 상황에서 실패 |

> 1080 Ti나 12GB GPU에서 학습하려면 **LoRA + gradient accumulation + 동결**을 반드시 알아야 합니다.
