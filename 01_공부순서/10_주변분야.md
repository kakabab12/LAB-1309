## 1. 강화학습 (RL) — 필요도 중

### 왜 알아야 하나
VLA 논문에 RL이 섞여 나옵니다(RIPT-VLA, VLA-RL, ConRFT 등). 또 "모방학습만으로는 한계가 있다"는 논의가 항상 나옵니다.

### 이 정도만 알면 됨

| 개념 | 뜻 |
|---|---|
| **MDP** | 상태 → 행동 → 보상 → 다음 상태 의 반복 구조 |
| **정책(policy)** | 상태를 받아 행동을 내는 함수. VLA도 정책입니다 |
| **보상(reward)** | 잘했는지 알려주는 숫자 |
| **가치함수** | 이 상태가 앞으로 얼마나 좋은가 |
| **탐험 vs 활용** | 새로운 걸 해볼까, 아는 걸 할까 |
| **on-policy / off-policy** | 지금 정책의 경험만 쓰는가, 과거 경험도 쓰는가 |
| **PPO** | 가장 널리 쓰이는 알고리즘 (이름과 용도만) |
| **offline RL** | 미리 모은 데이터만으로 학습 (실물 로봇에 중요) |
| **RLHF** | 사람 선호로 보상을 만드는 방식 |

### 모방학습과의 관계

| | 모방학습 | 강화학습 |
|---|---|---|
| 필요한 것 | 사람 시연 | 보상 함수 + 수많은 시행착오 |
| 실물 로봇 | 현실적 | **거의 불가능**(로봇이 부서짐) |
| 한계 | 시연 이상은 못함 | 보상 설계가 어려움 |

⭐ 그래서 로봇 분야는 **모방학습으로 시작 → RL로 미세 개선**이 주류입니다.

### 자료
- Sutton & Barto "Reinforcement Learning" 1~3장 (무료 PDF)
- 유튜브 David Silver 강의 또는 Hugging Face Deep RL Course

## 2. 3D 비전 — 필요도 중 (이미 절반은 아는 분야)

> ⭐ 인턴 때 핀홀 모델과 단안 depth를 직접 해보셨으니 **가장 쉽게 채울 수 있는 부분**입니다.

### 이 정도만 알면 됨

| 개념 | 뜻 | 이미 해본 것 |
|---|---|---|
| **핀홀 카메라 모델** | 크기 = 초점거리 × 실제크기 / 거리 | ✅ 안구간거리로 거리 추정 |
| **내부 파라미터(intrinsic)** | 초점거리, 주점 — 카메라 자체 특성 | ✅ 초점거리 추정 해봄 |
| **외부 파라미터(extrinsic)** | 카메라가 세상 어디에 어떻게 놓였나 | |
| **캘리브레이션** | 체커보드로 파라미터 구하기 | |
| **왜곡 보정** | 렌즈로 휘어진 영상 펴기 | ✅ 렌즈 보정 해봄 |
| **스테레오** | 두 카메라의 시차로 깊이 계산 | |
| **단안 depth 추정** | 신경망이 사진 한 장으로 원근 추정 | ✅ MiDaS 실시간 구동 |
| **포인트 클라우드** | 3D 점들의 집합 | |
| **hand-eye calibration** | 카메라와 로봇의 위치 관계 구하기 | |

### 로봇에서 특히 중요한 것

**hand-eye calibration** — 카메라가 본 위치를 로봇 좌표로 바꾸려면 필요합니다.
VLA는 이미지에서 바로 동작을 내기 때문에 **없어도 동작하지만**, 정확한 위치 기반 제어를 하려면 필요합니다.

### 실습 아이디어

```python
import cv2
# 체커보드로 카메라 캘리브레이션
ret, mtx, dist, rvecs, tvecs = cv2.calibrateCamera(objpoints, imgpoints, size, None, None)
print("초점거리 fx, fy:", mtx[0,0], mtx[1,1])
print("왜곡계수:", dist.ravel())
```

### 자료
- OpenCV 공식 튜토리얼 (Camera Calibration)
- Multiple View Geometry (책, 필요한 장만)

## 3. 제어 이론 — 필요도 하

### 이 정도만 알면 됨

| 개념 | 뜻 | 로봇에서 |
|---|---|---|
| **피드백 제어** | 목표와 현재의 차이를 줄이는 방향으로 | 모든 로봇 제어의 기본 |
| **PID** | 오차(P) + 누적(I) + 변화율(D)로 명령 계산 | 관절 제어기 내부 |
| **궤적 생성** | 시작점에서 끝점까지 부드러운 경로 만들기 | ⭐ **전환 연구와 직결** |
| **속도·가속도 제한** | 급격한 움직임 방지 | 안전, 저크 감소 |
| **임피던스/컴플라이언스 제어** | 힘을 조절해 부드럽게 접촉 | 사람과 협업, 삽입 작업 |
| **실시간성** | 정해진 주기 안에 반드시 응답 | 제어 루프 |

### ⭐ 전환 연구와 연결

궤적 생성에서 쓰는 기법이 **chunk 블렌딩과 사실상 같은 문제**입니다.

| 제어 이론 용어 | 우리 연구 |
|---|---|
| trajectory blending | chunk 블렌딩 |
| minimum jerk trajectory | 저크 최소화 궤적 |
| S-curve 속도 프로파일 | 부드러운 가감속 |
| via point | 경유점 = 전환 지점 |

→ **"minimum jerk trajectory"**를 검색해보면 우리 방법의 이론적 배경이 나옵니다.

### 자료
- "Modern Robotics" (Lynch & Park) — 무료 PDF와 유튜브 강의. 필요한 장만
- PID는 유튜브 영상 하나면 충분

## 4. ROS2 — 필요도 하 (연구실에 따라 상)

### 왜 알아야 하나
로봇 연구실이면 언젠가 씁니다. PiPER도 ROS2를 지원합니다. 다만 **우리 연구는 `piper_sdk`만으로도 됩니다.**

### 이 정도만 알면 됨

| 개념 | 뜻 |
|---|---|
| **노드(node)** | 하나의 프로그램 단위 |
| **토픽(topic)** | 노드끼리 메시지를 주고받는 통로 |
| **publisher / subscriber** | 보내는 쪽 / 받는 쪽 |
| **메시지 타입** | 정해진 데이터 형식 (예: sensor_msgs/Image) |
| **service** | 요청하고 응답받는 방식 |
| **launch 파일** | 여러 노드를 한 번에 실행 |
| **rviz** | 3D 시각화 도구 |
| **rosbag** | 데이터 기록·재생 ⭐ 실험에 유용 |

### 자주 쓰는 명령

```bash
ros2 node list                    # 실행 중인 노드
ros2 topic list                   # 토픽 목록
ros2 topic echo /joint_states     # 메시지 내용 보기
ros2 topic hz /camera/image_raw   # 주파수 확인
ros2 bag record -a                # 전부 기록
ros2 bag play rosbag2_xxx         # 재생
```

### 자료
- ROS2 공식 튜토리얼 (Humble 또는 Jazzy 버전)
- 실습은 **연구실에서 실제로 쓸 때** 하는 게 효율적입니다
