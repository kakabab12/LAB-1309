# 3단계. 모방학습과 Action Chunking (3~4주)

## 📌 쉬운 말 요약

**이 문서는 뭐 하는 곳?** 로봇이 사람 흉내로 배우는 방식과, **우리 연구의 핵심 개념**을 다룹니다.

**모방학습**: 사람이 로봇을 잡고 "이렇게 하는 거야"를 50번쯤 보여주면, 모델이 그걸 따라 하게 배웁니다.

**⭐ Action Chunk (동작 묶음)** — 이 문서에서 제일 중요합니다.
모델이 동작을 **한 개씩** 내놓으면 뚝뚝 끊깁니다. 그래서 **한 번에 50개씩 묶어서** 내놓고, 로봇은 그걸 차례로 실행해요.
문제는 **지시가 바뀌었을 때** 이미 받아놓은 50개를 어떻게 할지입니다. → **이게 우리 연구 주제입니다.**

**⭐ 공변량 이동** — 어려운 말인데 뜻은 간단합니다.
> 모델은 **연습 때 본 상황**만 잘합니다. 처음 보는 상황에 빠지면 엉망이 돼요.

"물건을 든 채로 다른 지시를 받는 상황"은 보통 연습 데이터에 **아예 없습니다.** 그래서 모델이 이상하게 행동할 거고, 그걸 고치는 게 우리 목표예요.

---

> ⭐ **연구 주제와 가장 직접적으로 연결되는 단계입니다.** 여기를 깊게 파세요.

## 3-1. 로봇이 배우는 방식

| 방식 | 설명 | 장단점 |
|---|---|---|
| **모방학습 (Imitation Learning)** | 사람 시연을 따라 배움 | 데이터만 있으면 빠름. 시연 이상은 못 함 |
| **강화학습 (RL)** | 보상을 받으며 시행착오 | 잘하면 강력. 실물 로봇에서 비현실적 |
| **모방 + RL** | 모방으로 시작해 RL로 개선 | 최근 흐름 |

→ **VLA는 거의 모두 모방학습**입니다. 우리도 모방학습입니다.

## 3-2. Behavior Cloning (BC)

가장 기본 방식: **(관측 → 동작)을 지도학습으로 흉내내기**

```
입력: 카메라 이미지 + 로봇 상태 + 언어 지시
출력: 다음에 할 동작
손실: 사람이 한 동작과의 차이 (L1 또는 MSE)
```

### ⭐ 공변량 이동 (covariate shift)

**이 연구의 이론적 근거가 되는 개념입니다.**

- 모델은 **사람 시연에 나온 상황**에서만 제대로 동작합니다
- 조금 틀어지면 → 학습에 없던 상황 → 더 크게 틀어짐 → **눈덩이처럼 실패**
- **"물체를 잡은 상태에서 다른 태스크 지시를 받는 상황"**은 일반 시연 데이터에 **아예 없는 상황**입니다
- → 그래서 모델이 이상하게 행동할 것이 예상되고, **전환 데모를 학습에 넣는 것**이 해법 후보가 됩니다

관련 개념: **DAgger** (실패 상황을 모아 다시 학습시키는 방법)

## 3-3. ⭐ Action Chunking

**전환 연구의 핵심 개념입니다.**

| 방식 | 설명 | 문제 |
|---|---|---|
| **한 스텝씩 예측** | 매 프레임 다음 동작 1개 | 동작이 떨리고, 추론 지연에 취약 |
| **Action Chunk** | 한 번에 **여러 스텝(예: 50개)** 예측 | 부드럽고 추론 횟수가 적음 |

### chunk 실행 방식

```
시각 0    : 모델 추론 → chunk [a1 ... a50]
            a1, a2, ... 를 차례로 실행
시각 t    : 남은 chunk를 버리고 새로 추론 → 새 chunk
```

**중요한 설정값**

| 설정 | 뜻 | 영향 |
|---|---|---|
| **chunk 길이** | 한 번에 몇 스텝을 예측하나 | 길수록 부드럽지만 반응이 늦음 |
| **n_action_steps** | chunk 중 **몇 개를 실행하고** 다시 추론하나 | ⭐ **전환 반응 속도를 직접 결정** |

→ `n_action_steps`가 크면 **지시를 바꿔도 한참 뒤에 반영**됩니다. **이 연구의 핵심 실험 변수**입니다.

### chunk를 이어 붙이는 문제

- 이전 chunk를 실행하는 중에 새 chunk가 도착하면 **두 개가 겹칩니다**
- 그냥 갈아끼우면 **동작이 튐(jerk)**
- 해법: **겹치는 구간을 가중평균으로 섞기(블렌딩)**, 또는 **Real-Time Chunking** 같은 방법
- ⭐ **이것이 "자연스러운 전환"의 기술적 핵심**입니다

## 3-4. 꼭 읽을 논문 (이 순서로)

| 순서 | 논문 | 여기서 얻을 것 |
|---|---|---|
| 1 | **ACT** (ALOHA) | action chunking이 왜 필요한지, temporal ensembling |
| 2 | **Diffusion Policy** | 다중 모드 동작 생성, 왜 평균이 문제인지 |
| 3 | ⭐ **Real-Time Chunking** (Physical Intelligence) | 추론 지연이 있을 때 chunk를 어떻게 이어붙이나 |
| 4 | (선택) **DAgger** | 학습에 없던 상황을 어떻게 보완하나 |

각 논문마다 [논문 노트](../02_논문노트/TEMPLATE.md)를 남기세요.

## 3-5. ⭐ 비동기 추론 (asynchronous inference)

**"저사양에서도 되는가"의 핵심입니다.**

```
동기(순차) 방식:
  관측 → [모델 추론 200ms] → 동작 실행 → 관측 → ...
  문제: 추론하는 200ms 동안 로봇이 멈춰 있음

비동기 방식:
  로봇 루프: 이미 받은 chunk를 계속 실행 (30Hz)
  추론 루프: 따로 돌면서 준비되는 대로 새 chunk 전달
```

- SmolVLA/LeRobot은 **추론 서버와 로봇 클라이언트를 분리**하는 방식을 지원합니다
- 로봇 쪽 PC는 저사양이어도 되고, GPU 서버가 추론을 맡습니다
- 공부할 것: 스레드/프로세스, 큐, **"최신 관측만 쓰고 밀린 것은 버리기"** 패턴

## 3-6. 평가 지표

| 지표 | 계산 방법 | 의미 |
|---|---|---|
| **성공률** | 성공 횟수 / 전체 시도 | 가장 기본 |
| **전환 반응 시간** | 지시 변경 시각 → 새 태스크 동작 시작 시각 | 얼마나 빨리 반응하나 |
| **jerk (저크)** | 가속도의 변화율. 궤적을 3번 미분 | 동작이 얼마나 튀는가 |
| **물체 낙하율** | 전환 중 떨어뜨린 비율 | 전환의 안전성 |
| **경로 길이** | 이동 거리 총합 | 불필요한 움직임 |

**jerk 계산 방법**: 관절값 또는 끝단 위치 시계열을 기록 → 시간으로 3번 차분 → 제곱 평균

## 3-7. 실습 과제

1. **ACT를 LeRobot에서 학습** — SmolVLA보다 가벼워서 1080 Ti에서도 편함
   - 공개 데이터셋 사용, 학습 곡선 확인
2. 학습된 ACT로 **chunk를 출력**해서 그래프로 그려보기
   - 50스텝 동작이 시간에 따라 어떻게 변하는지 눈으로 확인
3. **두 chunk를 가중평균으로 섞는 함수**를 직접 작성해보기
   - 이것이 나중에 전환 방법의 기초가 됩니다
4. `n_action_steps`를 1, 10, 50으로 바꿔가며 **동작이 어떻게 달라지는지** 관찰

## 3-8. 체크리스트

- [ ] 모방학습과 강화학습의 차이를 안다
- [ ] 공변량 이동이 무엇이고, 왜 "잡은 상태 전환"이 그 사례인지 설명할 수 있다
- [ ] action chunking이 왜 필요한지 설명할 수 있다
- [ ] `n_action_steps`가 전환 반응 속도와 어떻게 연결되는지 안다
- [ ] chunk 두 개를 부드럽게 섞는 코드를 작성할 수 있다
- [ ] 비동기 추론 구조를 그림으로 그릴 수 있다
- [ ] jerk를 계산할 수 있다
