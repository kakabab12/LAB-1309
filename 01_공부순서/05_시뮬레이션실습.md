# 5단계. 시뮬레이션 실습 — LIBERO + SmolVLA (3~4주)

> 여기부터는 **손으로 돌려보는 단계**입니다. 논문에서 본 것을 눈으로 확인합니다.

## 5-1. 준비물

| 항목 | 내용 |
|---|---|
| OS | **Ubuntu** (LIBERO는 Linux 전용) |
| Python | **3.12 이상** |
| PyTorch | 1080 Ti는 **2.7 + cu126** |
| GPU | 추론만 하면 1080 Ti로 충분할 가능성이 높음 |
| 디스크 | 데이터셋 약 2GB + 모델 수 GB |

## 5-2. 설치

```bash
git clone https://github.com/huggingface/lerobot.git
cd lerobot
```

PyTorch를 먼저 고정 설치 (1080 Ti)

```bash
pip install torch==2.7.1 torchvision==0.22.1 --index-url https://download.pytorch.org/whl/cu126
```

LeRobot과 LIBERO 설치

```bash
pip install -e ".[libero,smolvla]"
```

렌더링 백엔드 설정 (화면 없는 서버면 egl)

```bash
export MUJOCO_GL=egl
```

**설치 후 반드시 확인**

```bash
python -c "import torch; print(torch.__version__, torch.cuda.is_available(), torch.cuda.get_device_capability())"
```

> LeRobot 설치 과정에서 PyTorch가 최신 버전으로 바뀌었을 수 있습니다. 위 확인을 꼭 다시 하세요.

## 5-3. 첫 실행 — 작동 확인

태스크 1개만 3번 돌려서 환경이 뜨는지 확인합니다.

```bash
lerobot-eval --policy.path=HuggingFaceVLA/smolvla_libero --env.type=libero --env.task=libero_goal --env.task_ids=[0] --eval.batch_size=1 --eval.n_episodes=3
```

**여기서 확인할 것**
- [ ] 오류 없이 끝까지 도는가
- [ ] 성공률이 출력되는가
- [ ] GPU를 쓰고 있는가 (`nvidia-smi`로 확인)
- [ ] 1회 추론에 몇 ms 걸리는가

## 5-4. 기준 점수 측정 (중요)

LIBERO-Goal 전체(태스크 10개 × 10에피소드)

```bash
lerobot-eval --policy.path=HuggingFaceVLA/smolvla_libero --env.type=libero --env.task=libero_goal --eval.batch_size=1 --eval.n_episodes=10
```

> ⚠️ 논문 점수(LIBERO-Goal 92%)가 그대로 나오지 않는다는 보고가 여러 건 있습니다(사용자 보고 81~83%).
> **내 환경에서 나온 점수를 기준으로 삼으면 됩니다.** 전환 연구는 같은 환경에서의 **상대 비교**이기 때문입니다.

**기록할 것**: 날짜, GPU, LeRobot 버전, PyTorch 버전, 설정값, 결과 점수, 소요 시간

## 5-5. ⭐ 데이터 형식 직접 확인

문서만 보지 말고 **실제 값을 출력**해서 확인하세요.

| 항목 | 형식 |
|---|---|
| `observation.state` | **8차원** (끝단 위치 3 + 축-각 3 + 그리퍼 2) |
| `observation.images.image` | 정면 카메라 256×256×3 |
| `observation.images.image2` | 손목 카메라 256×256×3 |
| `action` | **7차원** (끝단 변화량 6 + 그리퍼 1), 범위 -1 ~ 1 |

**직접 해볼 것**
1. 관측을 한 스텝 받아서 shape과 값 범위 출력
2. 이미지 2장을 파일로 저장해서 눈으로 확인
3. 동작 7차원이 실제로 어떤 값으로 나오는지 100스텝 찍어보기
4. 그리퍼 값이 물체를 잡을 때 어떻게 변하는지 그래프로 그리기 ← **"잡은 상태" 판정의 기초**

## 5-6. ⭐⭐ 평가 루프 분석 (가장 중요)

**이걸 이해해야 전환 실험 코드를 만들 수 있습니다.**

코드를 읽으면서 아래 질문에 답하세요.

1. 언어 지시(task 문자열)는 **어디서** 모델에 들어가는가?
2. 모델은 **몇 스텝마다** 호출되는가? (`n_action_steps`)
3. 출력된 chunk는 **어디에 저장**되고 **어떻게 하나씩 꺼내 실행**되는가?
4. 새 chunk가 나오면 이전 chunk는 **버려지는가, 섞이는가**?
5. 에피소드 성공은 **누가 판정**하는가?
6. 관측 이미지는 어떤 **전처리**를 거치는가?

## 5-8. 🎯 첫 전환 실험 (공부의 결승선)

**목표: 태스크 A를 하다가 중간에 지시를 B로 바꾸기**

```
1. LIBERO-Goal에서 태스크 A로 에피소드 시작
2. N 스텝 뒤에 언어 지시를 B의 문장으로 교체
3. 나머지를 계속 실행
4. 영상 저장 + 성공 여부 기록
```

**관찰할 것**
- 로봇이 B로 넘어가는가, 아니면 A를 계속하는가?
- 동작이 튀는가?
- 물체를 들고 있었다면 어떻게 되는가?

**전환 시점 3가지로 나눠서**
| 시점 | 판정 방법 |
|---|---|
| 접근 중 | 그리퍼가 열려 있음 |
| **잡은 직후** | 그리퍼가 닫혔고 물체가 붙어 있음 |
| 놓기 직전 | 목표 위치 근처 |

이 실험 결과(영상 + 표)가 **중간 보고 자료**가 됩니다.

## 5-9. 자주 나는 오류

| 증상 | 원인 | 해결 |
|---|---|---|
| `MUJOCO_GL` 관련 오류 | 렌더링 백엔드 미설정 | `export MUJOCO_GL=egl` |
| 화면이 안 뜸 | 헤드리스 환경 | egl 사용, 영상으로 저장해서 확인 |
| `no kernel image` | PyTorch 빌드가 GPU 미지원 | 2.7 + cu126 재설치 |
| 관측 key 오류 | 이름이 정책 설정과 다름 | `observation.images.*` 규칙 확인 |
| 성능이 너무 낮음 | 절대/상대 제어 모드 불일치 | `--env.control_mode` 확인 |
| 재현이 안 됨 | seed·초기 상태 다름 | seed 고정, `--env.init_states=true` |
