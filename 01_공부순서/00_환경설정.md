# 0단계. 개발 환경 (1~2주)

> **이게 안 되면 뒤가 전부 막힙니다.** 가장 먼저, 가장 확실하게 끝내세요.

## 0-1. 왜 Ubuntu가 필요한가

| 이유 | 설명 |
|---|---|
| LIBERO가 Linux 전용 | LeRobot 문서에 `sys_platform == 'linux'` 로 명시되어 있음 |
| PiPER 제어 | 위고로보틱스 LeRobot 플러그인이 **SocketCAN**(리눅스 CAN 통신) 기반 |
| 대부분의 로봇 소프트웨어 | ROS2, MuJoCo 등이 리눅스 기준으로 개발됨 |

**선택지**

| 방법 | 장점 | 단점 |
|---|---|---|
| **Ubuntu 듀얼부팅** (권장) | 가장 안정적, CAN 통신 가능 | 설치가 번거로움 |
| WSL2 (Windows 안에서) | 설치 쉬움 | GUI 렌더링·USB CAN이 까다로움 |
| 연구실 Ubuntu PC 사용 | 바로 시작 | 내 마음대로 못 바꿈 |

> 시뮬레이션만 할 거면 WSL2도 가능하지만, **실물 로봇을 연결할 PC는 Ubuntu 네이티브**가 안전합니다.

## 0-2. 터미널 기본기

이 명령들은 손에 익어야 합니다.

```bash
pwd                      # 지금 어디에 있나
ls -al                   # 파일 목록 (숨김 파일 포함)
cd ~/projects            # 이동 (~ 는 내 홈 폴더)
mkdir -p a/b/c           # 폴더 만들기 (중간 폴더까지)
cp -r src dst            # 복사 (-r 은 폴더째)
mv a b                   # 이동/이름변경
rm -rf 폴더               # 삭제 (되돌릴 수 없음, 주의)
cat 파일                  # 내용 출력
head -n 20 파일           # 앞 20줄
tail -f 로그파일           # 실시간으로 뒤쪽 보기 (학습 로그 볼 때)
grep -rn "찾을말" .       # 폴더 전체에서 문자열 찾기
find . -name "*.py"      # 파일 찾기
du -sh *                 # 폴더 크기
df -h                    # 디스크 남은 용량
```

**꼭 이해할 개념**

| 개념 | 설명 |
|---|---|
| 절대경로 / 상대경로 | `/home/user/a` vs `./a` |
| 권한 | `chmod +x run.sh` (실행 권한) |
| 환경변수 | `export MUJOCO_GL=egl` — 프로그램 동작을 바꾸는 설정값 |
| `.bashrc` | 터미널 켤 때마다 자동 실행되는 설정 파일 |
| 백그라운드 실행 | `nohup python train.py &` / `tmux` (SSH 끊겨도 학습 유지) |

**tmux는 꼭 익히세요.** 학습이 몇 시간씩 돌아가는데, 터미널을 닫으면 꺼집니다.

```bash
tmux new -s train        # 새 세션 만들기
# Ctrl+b 누르고 d  → 빠져나오기 (프로그램은 계속 돎)
tmux attach -t train     # 다시 들어가기
tmux ls                  # 세션 목록
```

## 0-3. GPU 확인

```bash
nvidia-smi
```

**읽는 법**

```
| NVIDIA-SMI 550.xx    Driver Version: 550.xx    CUDA Version: 12.4  |
                                    ↑ 드라이버 버전      ↑ 드라이버가 지원하는 최대 CUDA
| GPU  Name        Persistence-M | Bus-Id  Disp.A | Volatile Uncorr. ECC |
|   0  NVIDIA GeForce GTX 1080 Ti |             | 2000MiB / 11264MiB   |
                                                    ↑ 지금 사용량 / 전체 VRAM
```

- **VRAM(11264MiB ≈ 11GB)**: 모델이 들어갈 수 있는 크기를 결정
- 학습 중에 `watch -n 1 nvidia-smi` 로 사용량을 지켜보면 배치 크기를 조절하기 좋습니다

## 0-4. ⭐ 가장 중요: 드라이버 / CUDA / PyTorch 버전 맞추기

여기서 대부분의 사람이 막힙니다. **구조를 이해하면 안 막힙니다.**

```
[GPU 하드웨어]  ← 세대(architecture)와 compute capability가 정해져 있음
      ↑
[NVIDIA 드라이버]  ← GPU를 컴퓨터가 쓸 수 있게 해줌
      ↑
[CUDA 런타임]   ← PyTorch 안에 포함되어 설치됨 (별도 설치 대개 불필요)
      ↑
[PyTorch]      ← cu126, cu128 처럼 어떤 CUDA로 빌드됐는지가 이름에 붙음
```

**우리 GPU의 세대**

| GPU | 세대 | compute capability | bf16 | 비고 |
|---|---|---|---|---|
| GTX 1080 Ti | Pascal | **6.1** | ❌ | 오래됨, 지원 끊기는 중 |
| RTX 4070 Ti | Ada | 8.9 | ✅ | 최신 코드 그대로 사용 가능 |

**1080 Ti 주의사항 (실제로 막히는 지점)**

- PyTorch 2.8 이상의 **cu128 / cu129** 빌드는 **Pascal 지원이 제거**됨
- **CUDA 13**은 Turing(20 시리즈) 이상만 지원
- 그냥 `pip install torch` 하면 최신 빌드가 깔려서 **GPU를 못 쓰게 될 수 있음**

**안전한 설치 (1080 Ti)**

```bash
pip install torch==2.7.1 torchvision==0.22.1 --index-url https://download.pytorch.org/whl/cu126
```

**설치 후 반드시 확인**

```bash
python -c "import torch; print(torch.__version__, torch.cuda.is_available(), torch.cuda.get_device_capability())"
```

기대 출력: `2.7.1+cu126 True (6, 1)`

- `False`가 나오면 → 드라이버 문제이거나 CPU 버전이 설치된 것
- `(6, 1)`이 안 나오면 → GPU 인식 실패

> 다른 패키지를 설치한 뒤 PyTorch가 **자동으로 최신 버전으로 바뀌는 일**이 자주 있습니다.
> 설치 작업을 할 때마다 위 확인 명령을 다시 돌리세요.

## 0-5. Python 가상환경

프로젝트마다 환경을 분리해야 버전 충돌이 안 납니다.

```bash
# conda 방식 (권장 - Python 버전까지 관리됨)
conda create -n lab python=3.12
conda activate lab

# venv 방식
python3.12 -m venv ~/venvs/lab
source ~/venvs/lab/bin/activate
```

- LeRobot은 **Python 3.12 이상**을 요구합니다
- 환경 이름을 프롬프트에서 항상 확인하는 습관을 들이세요: `(lab) user@pc:~$`

**설치한 버전 기록해두기** — 나중에 재현할 때 생명줄이 됩니다.

```bash
pip freeze > requirements_backup.txt
```

## 0-9. 자주 나는 오류

| 증상 | 원인 | 해결 |
|---|---|---|
| `torch.cuda.is_available()` False | CPU 버전 설치됨 | cu126 인덱스로 재설치 |
| `no kernel image is available` | GPU 세대 미지원 빌드 | PyTorch 2.7 + cu126 |
| `CUDA out of memory` | 배치가 큼 | batch_size 줄이기 |
| `ModuleNotFoundError` | 가상환경 활성화 안 됨 | `conda activate lab` |
| 학습 중 터미널 닫으니 중단 | 백그라운드 아님 | tmux 사용 |
