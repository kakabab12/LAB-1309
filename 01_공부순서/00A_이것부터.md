# 0-A. 진짜 처음이라면 이것부터

> 용어를 하나도 모르는 상태에서 읽는 문서입니다. **수식 없음, 영어 최소.**
> 여기만 이해하면 나머지 문서가 읽히기 시작합니다.

---

## 1. 우리가 하려는 것을 한 문장으로

> **"사람이 말로 시키면 로봇 팔이 알아서 움직이게 만드는 프로그램"**을 공부합니다.

예: "빨간 블록을 컵에 넣어" 라고 말하면 → 로봇이 카메라로 보고 → 팔을 움직여 집어서 넣음

그리고 우리 연구는 여기서 한 발 더 갑니다.

> **로봇이 일을 하는 도중에 "아, 그거 말고 파란 거"라고 말을 바꾸면 어떻게 되게 할까?**

---

## 2. 인공지능 모델이란 뭔가

**프로그램은 두 종류가 있습니다.**

| 옛날 방식 | 요즘 방식(딥러닝) |
|---|---|
| 사람이 규칙을 다 적어줌 | **예시를 잔뜩 보여주면 스스로 규칙을 찾음** |
| "손가락 사이 거리가 3cm 이하면 주먹" | 주먹 사진 1만 장을 보여주고 "이게 주먹이야" |

인턴 때 쓰신 **MediaPipe도 딥러닝 모델**입니다. 손 사진을 넣으면 관절 21개 위치가 나오는 것 — 그건 누가 규칙을 적은 게 아니라 **수많은 손 사진으로 배운** 거예요.

### 모델 = 아주 큰 계산식

- 모델 안에는 **숫자가 수억 개** 들어 있습니다. 이 숫자들을 **가중치(weight)** 또는 **파라미터**라고 불러요.
- "0.45B 모델"은 **그 숫자가 4억 5천만 개**라는 뜻입니다.
- 입력(사진)을 넣으면 이 숫자들과 곱하고 더해서 출력(관절 위치, 로봇 동작)이 나옵니다.

### 학습 = 그 숫자들을 고쳐나가는 것

```
1. 사진을 넣는다
2. 모델이 답을 낸다  → 틀렸다
3. 얼마나 틀렸는지 계산한다      ← "손실(loss)"
4. 숫자들을 조금씩 고친다        ← "학습"
5. 1~4를 수백만 번 반복
```

이게 전부입니다. 나머지는 이걸 **어떻게 빠르고 정확하게** 하느냐의 이야기예요.

## 3. 자주 나오는 단어 (일상어로)

| 단어 | 일상어로 바꾸면 |
|---|---|
| **모델(model)** | 훈련된 프로그램 |
| **가중치(weights)** | 모델 안에 든 숫자 뭉치. 파일로 저장됨(수 GB) |
| **파라미터 개수** | 모델의 크기. 클수록 똑똑하지만 무거움 |
| **학습(training)** | 숫자를 고쳐나가는 과정. 오래 걸림(몇 시간~며칠) |
| **추론(inference)** | 학습된 모델을 **쓰는 것**. 빠름(수십 ms) |
| **파인튜닝(fine-tuning)** | 남이 학습시킨 모델을 **내 데이터로 조금 더** 가르치기 |
| **체크포인트** | 학습된 가중치를 저장한 파일 |
| **데이터셋** | 학습에 쓰는 예시 모음 |
| **에피소드** | 로봇이 일을 한 번 처음부터 끝까지 한 기록 |
| **데모(demonstration)** | 사람이 로봇을 직접 움직여 보여준 시범 |
| **벤치마크** | 성능을 재는 시험 문제집 (예: LIBERO) |
| **정책(policy)** | 로봇의 두뇌. "지금 상황에서 뭘 할지" 정하는 것 |

## 4. GPU가 왜 필요한가

- 모델의 계산은 **덧셈·곱셈을 동시에 수백만 번** 하는 일입니다
- CPU는 어려운 일을 **순서대로 빨리** 하고, GPU는 쉬운 일을 **한꺼번에 엄청 많이** 합니다
- 그래서 딥러닝은 GPU를 씁니다

### VRAM (그래픽카드 메모리)

- 모델의 숫자 뭉치를 **올려놓을 공간**입니다
- 1080 Ti는 11GB → **11GB짜리 책상**이라고 생각하세요
- 책상보다 큰 모델은 아예 못 올립니다 → `CUDA out of memory` 오류
- **학습**은 추론보다 책상을 3~4배 더 씁니다 (원본 + 고칠 양 + 기록용)

그래서 문서에서 "7B 모델은 학습 불가, 0.45B는 가능"이라고 하는 거예요.

## 5. VLA가 뭔가

**V**ision(본다) + **L**anguage(듣는다) + **A**ction(움직인다)

```
[카메라 사진]  ┐
[사람 말]      ├→ [모델] → [로봇 팔을 이렇게 움직여라]
[지금 팔 자세] ┘
```

예전에는 "컵 집기 프로그램", "블록 옮기기 프로그램"을 각각 따로 만들었어요.
VLA는 **하나의 모델이 말로 지시받아** 여러 일을 합니다. 그게 새로운 점이에요.

## 6. 우리 연구를 아주 쉽게

### 문제 상황

로봇이 빨간 블록을 집으러 가는 중입니다. 그런데 사람이 말합니다.
> "아 잠깐, 파란 거로 해줘"

지금 모델들은 이럴 때 이런 문제가 생깁니다.
- 못 듣고 **하던 일을 계속** 함
- 갑자기 **홱 방향을 틀어서** 위험함
- 이미 **집고 있던 블록을 떨어뜨림**

### 우리가 할 것

이 상황을 **수백 번 실험해서**
1. 지금 모델이 얼마나 못하는지 **숫자로 보여주고**
2. 어떻게 하면 부드럽게 넘어가는지 **방법을 만들고**
3. 그 방법이 효과 있는지 **비교해서 증명**합니다

### 핵심 아이디어 하나

모델은 동작을 **한 번에 50개씩 묶어서** 내놓습니다(이걸 **action chunk**라고 해요).
로봇은 그 50개를 차례대로 실행하고 있고요.

그런데 지시가 바뀌면?
- **남은 것을 그냥 버리면** → 동작이 뚝 끊겨서 튐
- **끝까지 다 하면** → 반응이 늦음
- **이전 것과 새 것을 조금씩 섞으면** → **부드럽게 넘어감** ← 우리 방법

이건 이미 LAB 03에서 실험해봤고, 실제로 **저크(튀는 정도)가 9배 줄었습니다.**

## 7. 왜 시뮬레이션부터 하나

**시뮬레이션** = 컴퓨터 안의 가상 로봇 (게임 같은 것)

| | 진짜 로봇 | 시뮬레이션 |
|---|---|---|
| 실험 한 번 | 물건 다시 놓고 몇 분 | 자동으로 몇 초 |
| 500번 반복 | 며칠 | 몇 시간 |
| 실패하면 | 물건 떨어지고 위험 | 아무 일 없음 |
| 조건 맞추기 | 매번 조금씩 다름 | 완전히 똑같이 |

우리는 **LIBERO**라는 시뮬레이션을 씁니다. 그중 **LIBERO-Goal**은 물건 배치는 같고 **지시만 다른** 문제 10개라서, "말을 바꾸는 실험"에 딱 맞아요.

## 8. 도구 이름 정리

| 이름 | 정체 | 비유 |
|---|---|---|
| **Python** | 프로그래밍 언어 | 이미 쓰고 계신 그것 |
| **PyTorch** | 딥러닝 라이브러리 | 모델을 만들고 학습시키는 도구 상자 |
| **TensorFlow** | 다른 딥러닝 라이브러리 | PyTorch의 경쟁자 |
| **CUDA** | GPU를 쓰게 해주는 소프트웨어 | GPU 드라이버 같은 것 |
| **LeRobot** | 로봇 학습 라이브러리 | 데이터 모으고 모델 돌리는 도구 |
| **LIBERO** | 시뮬레이션 벤치마크 | 시험 문제집 |
| **MuJoCo** | 물리 엔진 | 게임의 물리 계산 담당 |
| **Hugging Face** | 모델·데이터 공유 사이트 | 딥러닝계의 GitHub |
| **SmolVLA** | 우리가 쓸 VLA 모델 | 주인공 |
| **PiPER** | 연구실 로봇 팔 | 6축 + 집게 |
